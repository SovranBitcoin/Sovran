## Broken

1. **Offline version-fetch test never checks that no fetch happened — fix.** `app/__tests__/ctaLatestVersionFetch.test.ts:128–136`. Both `it.each` rows set offline/current-version state and await `mount()`, then return without an assertion. `mount` at lines 39–43 only renders and flushes effects; neither it nor teardown asserts network calls. The adjacent offline cases do assert, but do not cover these native-version values. A regression that fetches for current/newer versions can therefore pass these named cases. **Evidence:** the real file passes all 14 tests. Executed the original callback extracted with the TypeScript parser in a Node VM, supplying a mount stub that records a fetch: it completes with one injected fetch and zero assertions. This probes the test callback, not a mutation of the real hook. **Failing-test idea:** make the hook fetch only for offline/current-version inputs; both table rows must fail. **Commit:** assert `mockGetLatestVersion` was not called after mounting in each row (and retain the cached-record assertion if that is part of the case). **Saved/network repair impact:** none; test assertions only, no product fetch behavior changes.

2. **Own-history split test passes if neither query answers — fix.** `nostr/__tests__/facade-own-state.test.ts:55–68`. The authored/replies test checks IDs only inside `kind === 'answered'` branches and never requires either outcome to be answered. Returning `unsupported` for both calls satisfies the test without testing the split at all. This is not the separate decision about retaining the public `getOwnHistory` API recorded in the surgery ledger; the existing behavioral test is defective regardless of that decision. **Evidence:** real file 4/4 passed; extracted original callback executed with both tier calls returning `unsupported`, completed with zero assertions. **Failing-test idea:** stub the relay-tier result to unsupported for authored/replies; the split test must fail. **Commit:** assert both outcome discriminants before narrowing and checking IDs. **Saved/network repair impact:** none; test assertions only.

3. **Notification scope tests silently accept unsupported outcomes — fix.** `nostr/__tests__/facade-notifications.test.ts:172–175,179–200`. The DIRECT/THREAD test checks neither discriminant before its conditional assertions, so both unsupported results pass. The preceding MENTIONS/ALL test asserts MENTIONS is answered but omits the equivalent ALL assertion; ALL can stop working without failing that check. **Evidence:** real file 10/10 passed; extracted original DIRECT/THREAD callback executed against a tier returning unsupported for both calls, completed with zero assertions. Neighboring fail-closed and MENTIONS checks already demonstrate the correct unconditional-discriminant pattern. **Failing-test idea:** return unsupported for DIRECT, THREAD or ALL independently; the corresponding test must fail. **Commit:** require answered for each result, then keep the existing ID/reason checks. **Saved/network repair impact:** none; test assertions only.
