## Broken

1. **B1 — Monthly totals silently stop at the first history page. Verdict: list.** W/screens/WalletScreen.tsx:79 reads `useHistoryWithMelts(100)` and takes only history/refresh; :285–288 hands that history to both monthly charts. T/components/MonthlyChart.tsx:156–175 filters/sums only those supplied entries. The underlying `wallet/src/react/useColadaTransactions.ts:315–328,333–352,362–371` initially reads page zero, refreshes only the head, and loads older entries only through `loadMore`. The 10-entry full-history screen has a separate page-size scope (:194–205), so scrolling there cannot fill the wallet's 100-entry scope. **Path:** cold-open a wallet with 101 settled 1-sat receipts this month; Received this month says 100, although 101 were received. Older payments in another currency also crowd this account's payments out. The counterparty panel (T/components/CounterpartyTransactions.tsx:41–55) has the same completeness assumption and no paging control. **Failing test idea:** provide 101 current-month receipts through a paginated manager and require a 101 total on wallet home without visiting history. **Repair boundary:** no saved shape or payment wire change is necessary; select a local period-total query or a deliberately complete read. Owner must choose the history-read strategy and loading presentation; merely raising 100 moves the defect.

2. **B2 — Liveness probes can dial a different host from the mint on the row. Verdict: list.** M/hooks/useMintPresence.ts:21–22 converts URLs to `normalizeMintUrlKey`; :40–41 reconstructs request URLs as `https://${key}`. `app/shared/lib/url.ts:86–104` deliberately strips `www.` for cache comparison. `app/shared/lib/cashu/mintHealth.ts:83–90,124–143` then fetches and records the verdict for that reconstructed address. **Path:** a visible `https://www.operator.example/mint` row with no fresh probe leads to a request for `https://operator.example/mint`; if only the original host serves a mint, the original row gets the other's offline verdict. This needs no HTTP mint or malformed URL. **Failing test idea:** feed the hook that www URL, capture `probeMints` arguments, and require the original address unchanged. **Repair boundary:** changes actual network destinations, hence always list; preserve original URLs for dialing and reserve cache keys for lookup. Owner must approve the distinction between comparison identity and request identity; no storage migration is proposed.

3. **B3 — A refreshed rating changes its number but keeps the old bar fill. Verdict: fix.** M/components/RatingBarChart.tsx:55–77 calculates a new `targetRow` and `goldPercentage`, but `hasAnimatedRef` prevents every subsequent update of `barScaleAnim`. Rows at :128–143 use the new target row with the old shared scale. Both M/screens/MintInfoScreen.tsx:602–606 and MintReviewsScreen keep the same mint key while reviews revalidate. **Path:** cached score 4.5 animates to 4.5/5 = 90%; a fresh score 3.0 moves the highlight to row 3, where it still fills 90% instead of 100%. The headline rolls to 3.0, so the two indicators disagree. **Failing test idea:** render 4.5, settle its animation, rerender 3.0 for the same mint, and require a scale target of 1. **Commit:** `fix(mint): update rating fill when the score changes`; retain one mount entrance and update the scale on later score changes. **Repair boundary:** presentation only; nothing saved or sent.

4. **B4 — Bulk cancellation bypasses the single-row in-flight guard. Verdict: list.** T/screens/TransactionsScreen.tsx:91–110 checks `inFlight` only in `handleCancelOne`; the sweep at :113–130 calls `reclaimOne` directly for every target. `app/shared/stores/runtime/rollbackStore.ts:55–72` uses a Set, not per-attempt ownership. **Path:** swipe pending send A to start its reclaim; before it resolves, press Cancel N pending. A remains in the pending target list and the sweep starts a second rollback for A. Conversely, while the sweep awaits A, a swipe can start B before the sweep reaches B. When either duplicate finishes, it clears the shared in-flight marker while the other is still outstanding. Coco may reject/serialize the extra action; the app has nevertheless dispatched it and can produce misleading partial-result counts. No double spend is asserted. **Failing test idea:** hold A's first rollback promise, invoke bulk cancel, and require only one rollback call for A and an in-flight marker until that call settles. **Repair boundary:** changes sequencing of network-facing cancel/reclaim operations; always list. Owner must choose whether bulk work joins or skips an existing per-operation cancellation, and how that counts in its result popup.

5. **B5 — A trusted-mint change during a list read can be lost. Verdict: list.** M/hooks/useMintManagement.ts:42–61 joins any existing `inflightLoad`; :139–152 handles mint-added/trusted/untrusted/updated events by invoking that same load. There is no dirty bit or trailing read. **Path:** a same-manager trusted-list query captures snapshot S; a mint is added/trusted before its promise continuation publishes S; the event handler joins that pending read, and both consumers publish S. After the promise clears, nothing rereads the updated list until a later event or remount. This is a separate invalidation defect from F207's already-recorded cross-manager ownership problem. **Failing test idea:** defer an old trusted-list result, fire `mint:trusted` after changing the fake manager's rows, resolve the old result, and require a second read plus the new mint. **Owner decision:** verify the deferred-result interleaving against the actual database/event ordering before approving a trailing invalidation read; no production timing reproduction was run. Retain coalescing and the existing account-reset ownership contract. **Repair boundary:** local list reads and React/cache state only; no saved fields or network payload changes.

## Inefficient

1. **E1 — Every mounted unit picker starts its own full keyset-unit read batch. Verdict: list.** W/hooks/useActiveUnit.ts:92 calls `useMintKeysetUnits`; W/hooks/useMintKeysetUnits.ts:26–43,72–85 gives each hook instance an independent initial `Promise.all` and mint-added/updated subscriptions. `app/shared/lib/cashu/managerInternals.ts:90–105` calls the keyset repository and scans keypairs per mint. W/screens/WalletScreen.tsx:72 and W/components/Account.tsx:78 each reach this hook. Account.tsx:229–250 mounts a PrimaryBalance for every available account; PrimaryBalance.tsx:359–363 mounts a UnitSwitcherPill, whose shared hook calls `useWalletPresentationUnit` and thus another `useActiveUnit`. **Cost evidence:** with N account pages and M trusted mints, these wallet-home consumers alone start at least `(N + 2) × M` local keyset reads per mount and can repeat those batches for one mint-update event; this excludes other mounted callers. Unknown units stay permissive, so these are overlapping reads of the same manager data, not distinct account queries. Source-derived call counts, not a latency benchmark; automatic render memoization does not coalesce separate mount effects. Owner must choose one manager-scoped shared reader or retain independent hooks after measuring. No speed-up or storage change is certified.
