### 1. Fixed-amount request display: identity, bootstrap and rejection — convert, S

- **Files/ranges:** `app/features/receive/screens/ReceivePaymentRequestQuoteScreen.tsx:67–195,197–254`.
- **Encoding:** parsed `entry.operationId`, `prState`, optional `rejection`, frozen `createdAt`, and separately resolved `p2pkKey`. The first three encode the receive display's phase; customization/key resolution are orthogonal inputs, not additional payment phases.
- **States/events:** waiting → claiming on matching `receive-op:prepared`; waiting/claiming → rejected(reason) on rolled-back; any nonterminal → received on finalized. Received absorbs later prepared/rolled-back. Mount and request-id replacement need explicit bootstrap transitions.
- **Illegal/reachable:** received or claiming with an old rejection is representable and **traced**: rolled-back sets rejection, prepared/finalized changes only `prState`. It is hidden by the synthetic entry's guard. A new request with the previous request's phase/time is also representable: rerender with different route params resubscribes but resets none of them. Missing bootstrap is **run** by the known-bug test. Existing **F179** owns the bootstrap/identity defect; do not file it again.
- **Persistence:** phase is local only. Per-op `creqCustomization` persists in profile `transaction-annotation-store:profile:<pubkey>`, field `annotations`, keyed `op:<operationId>`; defaults come from profile `mint-store` fields `creqP2pkLock`, `creqExcludedMints`. Keep these bytes/shapes unchanged; decode into an identity-bound local state and read the canonical receive attempt, not the request's synthetic receive id.
- **Consumers:** one phase reader file, the screen (event handlers, synthetic entry, customization visibility); timeline receives its derived history entry.
- **Pins/first additions:** `receivePaymentRequestQuoteScreen.test.tsx` pins matching, rejection, terminal absorption, unsubscribe, customization and malformed params. Replace its F179 quirk with canonical bootstrap/read-subscribe ordering; add request replacement and rejected→successful retry tests.
- **Conversion/deletion:** local discriminated union `{requestId, phase}` with reason only in rejected; reducer/events plus canonical snapshot bootstrap. Delete separate rejection state, status mapping ambiguity and identity-blind initialization. One file, plus tests; no general async-machine dependency needed.

### 3. Nearby durable delivery: carrier acknowledgements versus settlement — convert, M

- **Files/ranges:** `app/features/nearPay/lib/nearbyPayments.ts:45–112,146–243,244–370,383–421`; `app/features/nearPay/lib/nearbyPaymentStorage.ts:1–2`; pump in `app/features/nearPay/hooks/useNearbyDiscovery.ts:118–156`.

Receive and delivery flights are deliberately independent so a stuck mint cannot block outbound delivery.
- **Persistence:** secure vault `nearby-payment-journal`, version 1, `outbound` and `inbound`. Manifest key is `routstr_v1_<owner>_<sha256(name)>_manifest`, chunks use the same prefix plus slot/index. Preserve field names, defaults and exact payload/envelope bytes. Decode into runtime states using canonical Coco state; tolerate crash windows. Never tighten the saved schema to the new union.
- **Consumers:** one raw journal reader file (`nearbyPayments.ts`); two entry points in `useNearbyDiscovery.ts` (ingest/drain), plus `Colada.tsx` capture port.
- **Pins/first additions:** `nearbyPayments.test.ts`, `nearbyPaymentDmRetry.test.ts`, `nearbyDiscoveryLifecycle.test.tsx`; preserve exact-byte restart, rejected retention, write failure, owner checks and independent directions. Add crash cuts between every durable write/transport call and the F202 acknowledgement rule once timing policy is settled.
- **Conversion/deletion:** transition table plus two orthogonal carrier states and existing per-direction single flights. Delete optional-field guards and unused acknowledgement ambiguity; keep canonical money state outside the journal. M, with no stored/wire conversion.
