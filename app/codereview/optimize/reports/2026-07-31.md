# Optimizer run — 2026-07-31

Lenses: **content-shift, nostr-efficiency, lists-media** (first run — ledger
empty, all lenses tied; ties broken toward live runtime evidence and the active
`feat/notifications-unified` branch).

Scope: notifications + feed/thread surfaces, cashu DM transport, tiered nostr
read path.

Evidence: log-doctor `renders/perf/spans/waste/tiers/stats/visual/timeline`
over the day's session log (an idle polling segment + an interactive
feed/notifications segment). `log.txt` was 212MB — log-doctor refuses it whole;
the tail was sliced to a scratch file first.

Verification: every candidate was either refuted inline by direct code read or
handed to a fresh adversarial refuter subagent that saw only the code and the
claim. 8 of 17 candidates were refuted or dropped.

## Findings

### [P0] [CONFIRMED] `features/feed/hooks/useThread.ts:487` — Every thread revisit paints a full skeleton frame before swapping in cached content

The synchronous cache seed is applied in a post-commit `useEffect` while
`isLoading` initializes `true` and items `[]`, so even a fully cached thread's
first committed frame is the skeleton branch (target skeleton + sort tabs + 3
reply skeletons), swapped ~330ms later with rows shrinking 5→4.

- **Runtime:** `thread.shift.phase` cycled
  `loading-skeletons → fetching-with-skeletons(realReplies=2) → replies` three
  times in 30s for one thread.
- **Verification:** no lazy initializer, no mount gate, no reveal-on-settle
  mask exists; the seed's own doc comment ("paints the post… with NO network")
  states an intent the implementation misses — the seed lands on the second
  commit at best. `initialScrollIndex` (ThreadView.tsx:664) is doubly undefined
  on the frame FlashList honors it (isLoading true AND no target row yet).
- **Fix shape:** seed via lazy `useState` initializer (or gate the skeleton
  branch on a synchronous cache check) so cached threads never enter the
  skeleton phase; make `initialScrollIndex` computable on the first commit.

### [P0] [CONFIRMED] `features/feed/components/nostr/image-overlay/ImageBlock.tsx:127` — Recycled feed rows keep the previous image's aspect ratio; settled notes resize on load

`aspectRatio` is seeded from `getCachedAspect(url)`/imeta in a lazy `useState`
initializer that never re-runs when FlashList recycles the instance with a new
`url` (positional ``key={`b${i}`}`` in NoteContent:821), so both the module
aspect cache and imeta seeding are defeated on exactly the recycle path they
were built for. Only the new image's `onLoad` corrects it.

- **Runtime:** a note re-measured 403.67→336 (−67.67px) 32ms after its image
  aspect (0.8) arrived — content below jumps under the user's thumb mid-scroll.
- **Verification corrections:** the failure mode is *recycling*, not
  remounting (a true remount does consult the cache; `firstMeasure=true` logs
  are per-instance memory, not cache-miss evidence). The −67.67 trace is
  consistent with stale-recycle but static evidence can't rule out a wrong
  imeta `dim`; `recyclingKey={url}` resets only expo-image native state, not
  the JS aspect state.
- **Fix shape:** re-derive aspect when `url` changes (track last-url in state,
  or key the block by url).

### [P0] [CONFIRMED] `shared/lib/cashu/paymentRequestNostrTransport.ts:159` — DM envelope poll refetches the identical 50-envelope page every 15s with no cursor

`pollOnce` calls `getDmEnvelopes({limit: 50, refresh: true})` — no
since/high-water bound (the `DmEnvelopesRequest` surface only models `until`),
and `refresh:true` sets `no-store`/`no-cache`, deliberately defeating every
cache layer (transport.ts:132-178). `getDmEnvelopes` has no facade cache read.

- **Runtime:** 75 polls in a 19-minute idle session, 69 returning the same 50
  envelopes with `ingested=0` — ~50s of measured network time and 3,750
  envelope payloads for zero new information.
- **Verification:** no ETag/304 anywhere in `nostr/src`; `seenWraps` +
  gift-wrap cache save only client CPU, not transfer. nagg-tier.ts:420 comment
  concedes nagg stores arrival time so an incremental bound is possible. Scope
  limit: the relay floor's unbounded gift-wrap fetch (events=132 per failover)
  is documented-intentional (randomized wrap `created_at`) — incremental fixes
  help the nagg tier only.
- **Fix shape (app-side, no nagg change needed):** head-id short-circuit, drop
  `refresh:true` after the first tick, shrink steady-state limit; longer term
  expose a `since` bound on the request surface.

### [P1] [CONFIRMED] `shared/lib/cashu/paymentRequestNostrTransport.ts:187` — The poll can never stop: no backoff, no AppState gating, standing op keeps it alive for the app's lifetime

`stopPolling` fires only at `activeOps.size === 0`, but the standing payment
request is `singleUse:false` (wallet/src/payment-request-receive.ts:213-222)
and perpetually active, and coco re-activates transports on every boot — so
after one Receive visit the flat 15s `setInterval` runs forever.

- **Runtime:** poll ran continuously for the full 1126s idle session,
  `activeOps=15`.
- **Verification:** zero `AppState` usage in `app/shared/lib/cashu`,
  `app/shared/lib/nostr`, `nostr/src`, `wallet/src`; nothing detaches on
  screen unmount; STATE_MACHINE.md §11 (11.1–11.16) does not list this. The
  in-file "never remove it" comment defends the poll's existence against
  live-only refactors, not its cadence.
- **Fix shape:** background/foreground gating plus zero-ingest decay
  (15s → 60–120s); the live relay subscription already covers instant claims.

### [P1] [CONFIRMED] `features/feed/data/facadeNotificationsAdapter.ts:41` — Every notifications session update re-renders all ~28 mounted rows, even for invisible changes

`resolvedNotificationsToResult` builds brand-new object literals per
notification on every `snapshot()` (plus new metrics/profiles maps), and
`buildNotificationListItems` pushes fresh items even for unchanged rows — the
React Compiler bails (props genuinely change identity), so every
`NotificationListRow` re-runs date formatting, group titles, and timestamp
reduces.

- **Runtime:** 12 full item-array rebuilds in 35s with the screen open.
- **Verification:** worse than claimed — pool-count-only updates (nothing
  visible changes; pooled rows aren't in `snapshot()`) still trigger a full
  rebuild. No `React.memo`; identity destroyed at the adapter boundary
  regardless of merger stability. Frame-budget impact unmeasured.
- **Fix shape:** reuse item objects by id across snapshots at the
  adapter/grouping boundary; pass rows primitives instead of the whole result.

### [P1] [CONFIRMED] `features/feed/components/nostr/NoteContent.tsx:334` — Quoted-post chip balloons into a full card with no reserved space

Unresolved quotes render a ~36px chip that swaps in-place to an unbounded card
(avatar row + nested NoteContent, possibly media) when enrichment lands
post-paint — no min-height, no crossfade, no layout transition.

- **Verification scope-narrowing:** page-0 payloads ship resolved quotes and
  warm-nav cache paints reuse them — the shove-down hits cold loads/refreshes
  for quotes missing from the page-0 payload (`missingQuotedIds`) and live
  quote updates. The HomeFeed enrichment comment (HomeFeed.tsx:398-401)
  documents this exact reflow — instrumented, not mitigated. thread-skeletons.md
  has no quoted-post carve-out; its principles cut against the current chip.
- **Fix shape:** reserve a plausible min-height on the chip and crossfade the
  resolve, or include above-fold quote hydration in the first-paint gate.

### [P1] [CONFIRMED] `shared/lib/cashu/paymentRequestNostrTransport.ts:159` — Poll inherits a 30s timeout on a 15s cadence; a degraded nagg stalls delivery exactly when the poll is the only path

No `timeoutMs` is passed, so each tick can wait up to 30s on nagg (relay floor
also defaults 30s — worst case 30+30 sequential) before the sequential tier
engine tries the relay floor (which answers in <1s), while `polling=true`
suppresses the next tick (skipped, not overlapped).

- **Runtime:** nagg answer max 24.7s vs p50 211ms; relay fallback 491–755ms.
- **Verification:** tier engine is sequential-by-design with per-tier timeouts
  owned by each attempt; per-call `RequestControls.timeoutMs` is already
  plumbed through both tiers (`nagg-tier.ts:437`, `relay/tier.ts:308`). The
  stall matters precisely when the live socket is down — the poll's
  raison d'être scenario.
- **Fix shape:** pass a tight per-poll budget (~8–12s).

### [P2] [CONFIRMED] `shared/lib/contentShiftLog.ts:862` — Overlap/order-break analysis compares stale rects and truncates keys to 18 chars, manufacturing phantom evidence

The `measuredRows` filter keeps any row with a `lastRect` regardless of age
(staleness is computed at :813 but only used as a display flag), so rects
captured at different scroll offsets are compared — producing
scroll-delta-sized "overlaps" (1849px) and "order breaks" (−1677px) — and
`itemKey.slice(0, 18)` renders every grouped notification key as exactly
`notification:group`, faking duplicate keys.

- **Impact:** this run burned a verification pass disproving a
  FlatList-corruption theory this artifact suggested; it will poison every
  future content-shift/visual investigation until fixed.
- **Fix shape:** exclude stale rects from the pair analysis; widen the key
  slice.

## Refuted this run (dropped)

- **Notification row id-flip remounts** — target-keyed id space is pinned by
  tests on both sides of the merger boundary
  (`__tests__/notificationGroups.test.ts` "row id stability", merger test
  "late nagg upgrades … in place"); nagg never emits `type:'single'` for
  batchable reasons. Residual: multi-`e`-tag reactions can produce a duplicate
  row (cosmetic dedup edge), never a remount.
- **Reply-bar height settle (80→86.33)** — `replyBarHeight` algebraically
  cancels out of `paddingBottom` whenever `focusReserve` is positive; in the
  clamped regime the delta is off-screen trailing padding.
- **Avatar placeholder flash** — placeholder renders *under* an always-mounted
  expo-image; memory-cache hits paint the same frame; the 182 avatar-loading
  measurements are a mount counter (cluster avatars × mounts), not flash
  evidence.
- **Wallet single-use op "leak"** — persist-until-paid is documented
  intentional design (`wallet/src/history/aggregate.ts:39-44`; cancelling
  would strand a payer's ecash); poll cost is flat in op count. Hygiene
  kernel worth remembering: coco ops have no expiry field and `incoming.list()`
  grows monotonically; any future fix must respect persist-until-paid.
- **NPC since-cursor "stuck at 0"** — first-run artifact (store writes only
  after a processed quote); advancing it app-side races the plugin's
  failure-retry watermark and risks silently dropping paid quotes. The
  25s-interval-alongside-websocket half survives as a lesser cadence/gating
  finding (not reported this run; websocket connectivity is optimistic and
  undetectably dead, so the interval is the designed backstop).
- **Primal 60s repoll** (survived, narrowed, not reported) — network-only cost
  (~1 unbounded 50-item query/min while focused), focus-scoped teardown is
  correct, absorb path is no-op-cheap, and the live+poll idiom is documented;
  upstream `since` support unverifiable from this repo.
- **ownContent-driven session teardown** (survived, static-only, not
  reported) — `ownEventIds` memoized on the `byId` object identity tears down
  the three-source session via `useFocusEffect` dep churn on a mid-focus
  own-content lifecycle write; rarer than claimed (zustand no-op guards).
  Candidate for a future run if runtime evidence appears.
- **FlatList vs FlashList on notifications** (survived, not reported — slot
  budget) — `List.tsx` docstring names the convention; NotificationsScreen
  uses core FlatList with default windowing (27–28/28 rows mounted). Largely
  mitigated if the adapter identity-churn fix lands first; migration cost:
  FlashList recycling never re-fires `onLayout` for same-size rows, which
  interacts with the per-row `VisualLayoutProbe`.
- **HomeFeed instrumentation gap** (confirmed, filed under verification gaps).
