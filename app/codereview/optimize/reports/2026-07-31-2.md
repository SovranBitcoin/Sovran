## Findings

### [P1] [CONFIRMED] `app/shared/lib/cashu/manager.ts:523` — Coco `Manager` is constructed with the `subscriptions` config slot undefined and its pause API unused; a dropped WebSocket degrades to 5s HTTP polling for the life of any pending mint state, with no AppState gating

The single `new Manager(...)` call site passes 5 of 9 constructor args —
`subscriptions` (slot 8) is undefined, so coco-core applies hardcoded
`slowPollingIntervalMs: 20_000` / `fastPollingIntervalMs: 5_000`
(`@cashu/coco-core/dist/index.js:13241-13249`). Coco's WebSocket transport is
**one-shot per mint — no reconnection on failure** (HybridTransport doc
comment), so after a drop, every mint with pending quotes / inflight proofs is
HTTP-polled at the 5s fast cadence until that state settles. `Manager` exposes
`pauseSubscriptions()` / `resumeSubscriptions()` (`index.d.ts:725-726`) —
zero call sites in the app; nothing wires AppState.

- **Runtime:** 68-minute idle session: `ws_closed → hybrid-transition` cycles
  early, `polling_task_error` twice, then sustained idle mint traffic
  (46x POST mint.sovran.money in 11min, 40x POST mint.minibits.cash in 10min).
- **Verification corrections:** polling is NOT unconditional — it only runs
  while genuinely-pending subscriptions exist (ProofStateWatcher stops on
  `spent`; a fully-settled wallet polls ~zero). "No app-side way to pause" was
  wrong: two unused local fixes exist. The observed ~14–15s cadence doesn't
  cleanly match 5s or 20s alone (likely interleaved subscriptions); per-host
  attribution is plausible-not-proven. The ldk.thesimplekid GETs (~1/2.9min)
  match NEITHER this mechanism nor NPC — unattributed.
- **Fix shape:** pass `subscriptions` config (slower intervals) in the
  constructor and/or wire `pauseSubscriptions()/resumeSubscriptions()` to an
  AppState listener in `CocoProvider`; consider WS reconnect upstream.

### [P1] [CONFIRMED] `app/shared/lib/cashu/npc.ts:14` — NPC sync is an always-on 25s poll layered ON TOP of healthy websocket pushes, never paused, its pause API unused

`NPC_SYNC_INTERVAL_MS = 25_000` is armed via `autoStart: true`
(`manager.ts:999`). Reading the plugin source
(`coco-cashu-plugin-npc/dist/index.js:252-298`): `armIntervalTimer()` is
rescheduled in the `finally` of EVERY sync run regardless of trigger — the
interval is not a dead-websocket backstop, it fires at full cadence while the
websocket is healthy and pushing. Zero `AppState` references in
`app/shared/lib/cashu/`, `wallet/`, `nostr/` (OfflineProvider's AppState
listener is network-check-only). The plugin exposes its own
`pauseSubscriptions()/resumeSubscriptions()` (stops timer + websocket) —
unused.

- **Runtime:** 161 syncs in 68 idle minutes; 148/161 used the cached JWT
  (300s TTL / 25s ≈ 12:1 — matches), so steady-state is ~1 HTTP round trip
  per 25s, forever, for a receive feature not in use.
- **Verification correction:** the earlier "designed backstop" framing
  (run 1's NPC refutation) understated it — the interval is unconditional,
  which STRENGTHENS the gating case. Per-tick cost is modest; the 4.3s avg
  may blend boot-time syncs.
- **Fix shape:** AppState-gate (pause on background, resume+sync on
  foreground) and stretch the interval when the websocket is healthy /
  after N consecutive `no_new_quotes`.

### [P1] [CONFIRMED] `features/mint/screens/MintListScreen.tsx:267` — `isExecuting` flips re-invoke `renderItem` for every visible mint row with unchanged items; each re-invocation mints a fresh `MintIdentity` and refires ContactRow's effect

React Compiler does NOT rescue this: `renderItem` (`:259`) is a plain
lowercase closure invoked externally by FlashList's `ViewHolder`
(`ViewHolder.js:32-38` memoizes on `[item, extraData, target, renderItem]`),
not a compiled component boundary. When `isExecuting` flips, both the
`renderItem` closure identity (deps include `handleMintPress` ←
`isExecuting`, `:188-202,:283`) and `extraData={isExecuting}` (`:322`)
change, failing ViewHolder's memo for every mounted cell — same items,
full re-invocation, fresh `mintIdentity(item)` object each time (`:267,:292`).
`ContactRow.tsx:1038` then lists the raw derived `mint` OBJECT in its effect
deps alongside the extracted primitives (`:1041-1051`), so the effect (and
`contact_row.mint.render`, `:982`) refires with no displayed field changed.

- **Runtime:** 52 `contact_row.mint.render` logs/session — consistent with
  visible-rows × isExecuting toggles/mounts, not with per-content-change.
- **Fix shape:** make `renderItem` identity independent of `isExecuting`
  (read it inside via ref/store), stop passing it as `extraData` if rows
  don't display it, and key ContactRow's effect on primitives only.

## Refuted this run (dropped)

- **[was P0] reset-mid-commit loses the payment** — history is projected
  straight from coco operation repositories (`history/aggregate.ts:5-7`,
  written in `executeMelt` BEFORE the machine sees the result) and the
  confirmation toast comes from coco `melt-op:finalized` with an explicit
  "background melt (no active toast) → show new confirmed toast" branch
  (`usePaymentStatusListener.ts:786-857`). The commit guard's own comment
  (`createMachine.ts:254-256`) and STATE_MACHINE.md §4 sanction late-result
  discard. Only the metadata residual above survives.
- **Screen-action double-submit** — the mutex lives one layer down:
  `useSingleFlight` (sync ref check-and-set) wraps every `onPress` in the
  shared `Pressable` primitive (`Pressable.tsx:103-111`), and direct RN
  Pressable imports are ESLint-blocked. `execute()` itself genuinely has no
  guard — but no UI path can reach it twice.
- **`useReusableMintQuote.rotate()` stale write** — colada's module-level
  `inFlight` Map keyed by `reusableQuoteKey` (`quotes/reusable.ts:70,102,145`)
  serializes rotate against concurrent ensures in every ordering; ensure
  during rotate returns the rotate promise itself. Residual kernel: the
  hook-level guard asymmetry only matters if the lower layer ever stops
  sharing that map.
- **Transactions `account` inline-object memo break** — React Compiler
  compiles the screen and all 11 components bailout-free
  (react-compiler-healthcheck); the prop object is memoized keyed on
  `selectedCurrency` and stable across month-pill re-renders.
- **Transactions filter/sections re-run on reference churn** —
  `useColadaTransactions` explicitly preserves identity on unchanged content
  (`sameTransactionList`/`sameAnnotatedList`, wallet/src/react/
  useColadaTransactions.ts:371-406); the measured 106ms filter passes are
  genuine-change recomputes.
- **MonthlyChart whole-map selector** — the wholesale-replace + full-map
  subscription is real but its writers are 4 call sites all in
  `useMintRebalanceOrchestrator` (rare, user-initiated), and the 51x counter
  is an effect gated on derived outputs, not renders — mechanism/metric
  decoupled. Not steady-state waste.
- **AnimatedBackgroundView children memo defeat** — compiler-memoized JSX
  subtrees keep `children` referentially stable; LayoutDebugWrapper,
  BackgroundView, WalletScreen all compile 100% bailout-free. The 122x
  `bg.view.render` more likely traces to the component's own
  `useSyncExternalStore`/context reads (`BackgroundView.tsx:303,316-317`) —
  future-run lead, unverified.
- **pricelistStore duplicate-tick writes** — every hot consumer selects
  primitives through `getBtcPrice` (Object.is filters duplicates);
  the only churning subscriber is `PricelistProvider`, whose context has zero
  external consumers. Store-side equality guard would be hygiene, not perf.
- **imageCache unbounded prefetch fan-out** — expo-image funnels every
  prefetch through natively-capped queues (SDWebImagePrefetcher iOS /
  Glide Android), so `Promise.all` creates queue backlog, not bandwidth
  contention — which better explains the 10.1s max as queueing latency.
  The never-evicted `prefetchedUrls` Set is KB-scale. (222 spans / 276s IS
  correctly attributed to `imageCache.ts:61` — worth a look for prefetch
  volume policy someday, but the claimed mechanism was wrong.)

## Skill updates

- **sovran-payments**: "Standing coco services expose pause/resume
  (`Manager.pauseSubscriptions/resumeSubscriptions`, NPC plugin equivalents)
  and a `subscriptions` interval config slot — any always-on wallet service
  must have an AppState story; never arm an interval without one."
- **sovran-ui**: "FlashList `renderItem` is a plain closure, not a compiled
  component boundary — React Compiler does not memoize objects built inside
  it, and a state-dependent `renderItem`/`extraData` identity re-invokes
  every visible row. Keep `renderItem` deps static and pass primitives to
  row-level effects."
- **sovran-quality**: "Before flagging inline-object / children-break-memo
  render findings, run `npx react-compiler-healthcheck --src <file>` —
  bailout-free compilation refutes the classic patterns (this run: 4 such
  candidates died to it)."
- **sovran-payments**: "History and payment toasts are sourced from coco
  events/repositories, not machine callbacks — machine-callback-only side
  effects (annotations, linking, geotag) are the fragile place; put
  must-not-miss side effects on `melt-op:finalized`/`send:finalized`."
