# 📈 Self-Improving Rule for React Native / Expo Projects

This rule ensures that Cursor continuously improves the project's rule system as the codebase evolves.  
It applies globally and governs how all other rules should be created, updated, organized, and deprecated.

---

## 1. Detect When New Rules Are Needed

Cursor should automatically analyze recent changes to the React Native / Expo codebase and determine when new rules must be created.

### Trigger new rules when:
- New folders are added (e.g., `/features/notifications/`, `/services/auth/`)
- New architectural patterns emerge (e.g., introduction of custom hooks, stores, utility modules)
- New UI patterns appear (e.g., repeated layout styles, new design components)
- New Expo functionality is adopted (e.g., FileSystem, Haptics, Notifications)
- Patterns appear 3+ times without an existing rule covering them

### When triggered, Cursor should:
- Create a new rule in `.cursor/rules/auto/` with:
  - description
  - globs targeting new file patterns
  - consistent code examples drawn from the project
  - "good vs bad" sections
  - clear conventions based on React Native best practices

---

## 2. Keep Existing Rules Up-to-Date

Cursor should automatically revise rules when the codebase evolves.

### Update a rule when:
- The rule's globs no longer match new directory structures  
- New naming conventions emerge (e.g., snakeCase → camelCase files)
- Project switches styling system (e.g., StyleSheet → NativeWind)
- Project adopts new navigation (e.g., React Navigation, Expo Router)
- Types or interfaces evolve
- Components adopt new patterns such as:
  - `useCallback` / `useMemo` optimization
  - Expo Router conventions
  - Better shared UI patterns

### Update contents by:
- Rewriting examples to match **current** project patterns  
- Removing deprecated example patterns  
- Updating recommendations to use modern Expo APIs and patterns  

---

## 3. Enforce Rule Quality & Consistency

All rules generated or updated must follow this structure:

### Required metadata
```yaml
---
description: ""
globs: []
alwaysApply: false
---
```

### Required markdown sections

* **Purpose**
* **Good Examples**
* **Bad Examples**
* **Enforced Patterns**
* **Maintenance Notes**

Avoid vague instructions — every rule must be explicit, actionable, and in the context of React Native + Expo.

---

## 4. Rule Naming & Organization

* All rule files must use **kebab-case**:
  `react-native-components.mdc`, `expo-notifications.mdc`, `api-services.mdc`
* Category folders:

  * `.cursor/rules/ui/` – styling, components, layout, animations
  * `.cursor/rules/logic/` – hooks, services, stores, utilities
  * `.cursor/rules/app/` – navigation, Expo modules, app architecture
  * `.cursor/rules/auto/` – rules autogenerated by Cursor

Rules in `/auto/` must be reviewed and promoted to a main category if they remain relevant for > 2 weeks.

---

## 5. Deprecate Rules When Necessary

Cursor should detect obsolete or unused rules.

### Deprecation criteria:

* Rule references APIs or project patterns no longer in use
* Rule globs point to folders that no longer exist
* Rule contradicts a newer rule
* Rule hasn't matched any file edits in the last 60 days

### Deprecation workflow:

1. Move to `.cursor/rules/deprecated/`
2. Add metadata:

```yaml
deprecated: true
```

3. Add a "Migration Notes" section explaining which modern rule replaces it

---

## 6. Maintain Alignment with React Native + Expo Best Practices

Rules should reinforce up-to-date, idiomatic RN/Expo patterns:

* Use **functional components** and **TypeScript** (no `any`)
* Prefer **Expo APIs** over custom native modules where possible
* Use **NativeWind** or consistent styling methodology
* Use **Expo Router** or consistent navigation patterns
* Use hooks for domain logic:

  * `useAuth()`, `useSync()`, `useTheme()`, etc.
* Prefer strongly typed models/interfaces
* Avoid overly complex prop drilling → use context or hooks

Cursor should automatically update the rules when Expo SDK updates introduce new recommended APIs.

---

## 7. How Rules Should Interact with Code Changes

Whenever the project changes significantly:

* Add or update rules for:

  * New screens
  * New design components
  * New context providers
  * New services (auth, sync, storage)
  * New Expo features (camera, files, biometrics, etc.)
* Update folder-specific rules if:

  * Folder structure changes
  * Module responsibility changes

---

## 8. Continuous Review

On each commit or batch of changes, Cursor should:

1. Scan modified files
2. Identify mismatches with existing rules
3. Suggest fixes or rule updates
4. Propose new rules when new patterns consistently emerge
5. Flag rules that no longer apply

---

## 9. Guardrails (Prevent Rule Bloat)

Cursor must **not** generate rules for:

* One-off patterns
* Very small modules
* Temporary experimental code
* Personal preferences that aren't stable in the codebase

Rules should reflect **consistent, repeated project behavior**, not isolated events.

---

## 10. Final Enforcement

Cursor must:

* Follow this rule before applying any other rule
* Prioritize consistency and maintainability
* Keep the rule system clean, modern, and aligned with the evolving React Native / Expo project
