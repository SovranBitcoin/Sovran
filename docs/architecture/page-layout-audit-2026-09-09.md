# Page layout audit — 2026-09-09

Source review covers every UI route under `app/app`: **108 routes**, including **7 tab routes**. Layouts, `+html.tsx`, and `+native-intent.tsx` are infrastructure and excluded. Aliased route entries are listed separately because they can inherit different navigators. This is a source audit and migration inventory; it does not establish runtime verification on iOS or Android.

## Shared conventions

- Native iOS tabs and docked JavaScript tabs have different viewport ownership. Read the scoped shared inset convention instead of reconstructing tab height or branching on OS in page content.
- `Screen` owns ordinary scrolling pages and measured footers. `List screen` and `ScreenScrollView` consume the same remaining bottom clearance for custom page scrollers.
- Safe-area frames consume the inset once. Nested content must not add the same system inset again.
- Page spacing is separate from navigation clearance. Preserve content spacing through `bottomSpacing`; do not encode navigation height in fixed `pb-*` values.
- Chat, thread, camera, stories, composer, map, and pager layouts retain explicit ownership where their viewport or overlay geometry requires it. Horizontal lists are not page scrollers.

## Completed conventions and retained owners

- Mint info and reviews now use Screen with measured BottomButtons, including the reviews empty state. Merchant detail and rail lists use ScreenScrollView; their existing top/header layout remains intact.
- Signer activity uses List screen; the animated signer detail scroller uses the shared bottom hook with manual adjustment.
- Profile UserFeed uses List screen for modal and card profile routes.
- The map control overlay uses remaining bottom inset + 16.
- BackgroundScreen retains its pager height subtraction; adding an outer bottom frame would count the same safe area twice.
- SettingsRoutingScreen, SettingsNetworkScreen, and SettingsNotificationPolicyScreen now use ScreenScrollView inside their safe-area frame, avoiding automatic inset duplication.
- Custom page scrollers consume measured footer clearance, including footer appearance/removal and text wrapping. Mint selection and balance split no longer need fixed 120-point reserves; transaction history no longer needs 250.
- Search result lists and recent-search content both use the page convention under Wallet, Feed, and Contacts.
- Contacts measures its floating setup banner and reserves that clearance in both contact and group lists. Feed reserves its floating compose button height and gaps.
