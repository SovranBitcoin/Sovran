---
id: F105
title: "Adopting leftover stores skips a destination that holds the wrong data"
priority: medium
needs: fix
---

The leftover-adoption loop in `app/shared/lib/migrations/globalMigrations.ts` writes each bare store to the
owner's key and reads it back, returning run-again when the readback differs. On the next launch it skips any
destination that is not empty, so a destination left holding different data by the failed write is never corrected
and the migration then records itself complete.

Found by a Codex trial audit of commit 6bfa04c13 on 2026-10-11, which injected the fault into the exact function:
first run `run-again`, second run `completed`, wrong destination unchanged. `preProfileUpgrade.test.ts` covers an
absent write only. Whether native storage can produce a non-empty wrong value is not established.

## Done when

A destination that differs from its source is not treated as adopted, with a test for the non-empty mismatch.
