Private message plaintext persists in AsyncStorage at **three** sites, not the one this entry used to name. (a) `createPubkeyScopedCache.ts` backs both `nip04Cache.ts` (NIP-04 plaintext) and `giftWrapCache.ts` (NIP-17 `UnwrappedDM`) — fix the factory, not the call sites. (b) `app/features/bitchat/stores/bitchatDmMessages.ts` persists `byPeer[].content` for BLE 1:1 messages marked `isPrivate: true`. Make plaintext memory-only, or design encrypted storage with retention. Blobs already written (`nip04-cache:v1`, `nip04-cache-neg:v1`, `nip17-unwrap-cache:v1`, `nip17-unwrap-cache-neg:v1`, and the bitchat DM store) hold plaintext on disk, so the change must also erase them.

**Handed to the owner on 2026-10-11.** How these messages are kept is a choice about what the
person using the app sees, so no code was changed. Facts found: the two Nostr caches exist so
the message list opens without decrypting again, and with a remote signer every decryption is a
round trip to the signer; the nearby-chat store is the only copy of those messages; nothing in
the app encrypts a stored blob today, so option A adds that.

Which should it be?

- **A (recommended). Keep them on the phone, encrypted.** Messages still open at once. The key
  sits in the phone's secure storage per account, so a copied backup or a file pulled off the
  phone cannot be read. Old unencrypted copies are erased on first launch.
- **B. Keep nothing on the phone.** Messages are decrypted again on every launch, which is slow
  and, with a remote signer, asks the signer for each one. Nearby-chat history is gone after a
  restart. Old copies are erased.
- **C. Leave as is and record why.** The wallet's ecash sits in the same app storage, so
  message text is no worse protected than the money.

## Done when

Safe key migration; no plaintext at rest at any of the three sites, including blobs written before the fix; offline and profile-isolation tests
