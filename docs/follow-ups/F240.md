Found by the pass 3 survey (`.surgery/pass-3/surveys/feed-social-nostr.md` D1 to D5; traced, not run). The own relay list has two
publishers (first run and Network settings) with different rules. (1) A relay edit made before the first-run publish
is marked published and never sent, and the next start ignores the copy on the relays. (2) After the first-run
publish the saved list is empty, so adding one relay makes it the only relay and publishing drops the defaults from
the public list (pinned in the tests without a quirk mark). (3) "Publish relay list" dates the event to the current
second, not after the list it replaces, so relays can keep the older list while the app records success. (4)
Removing every relay publishes an empty list while the app keeps writing to the defaults. (5) A profile edit can be
built on an older profile when a relay has not answered within three seconds, overwriting fields another client set:
the "build only on a complete read" rule pass 2 gave follows. Left because every repair changes what is published
or the saved `source` field. One owner for "read the newest own replaceable event, change it, publish it to the
relays read" (the survey's candidate 10) would settle them together; it also changes when the mute list publishes,
which is the choice in F227.

## Done when

The owner has ruled; relay list, profile, mute list and follows share one read-change-publish rule, each with tests.
