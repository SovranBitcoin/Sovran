The Nostr data changes were proved with counted tests over fake sockets: requests per source for
a cold list, signature verifications for an inbox replay, dials to a dead relay, which accent node
a person row renders. Nothing was run on a phone or against live relays. Not yet seen:

- Whether the device runs cooler: CPU while the gift-wrap inbox is replayed on a reconnect and
  on return to the foreground, with a real inbox.
- Whether Primal's cache accepts many requests on one socket as the shared connection in
  `nostr/src/facade/primal/protocol.ts` sends them, answers `contact_list` with
  `extended_response: false` with the kind-3 alone, and tolerates `CLOSE` for a cancelled
  request.
- Whether the default relays honour `limit: 0` on the second filter of a resumed gift-wrap
  subscription (`nostr/src/facade/relay/protocol.ts`). A relay that treats it as "no limit"
  replays the inbox as before; one that rejects the REQ would leave that relay to the poll.
- Cold start on Contacts: saved names and avatars on the first frame, and no refetch of profiles
  saved within a day (`nostr.facade.profiles_boot_seeded` in the log, and one
  `nostr.read.profiles.request` per frame of new rows).
- The person row (`ContactRow` with `reserveAccentLine`): that a row with no NIP-05 and no stats
  is the same height as one with them at default and large text sizes, and that the empty line
  reads as intended.
- A payment request paid, and ecash received by message, with the relay tier switched off in
  Settings → Network, and after backgrounding and returning.

## Done when

Each item has been run on iPhone and Android with the result recorded, and anything that did not
hold has its own entry.
