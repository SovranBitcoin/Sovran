id: F261
title: "Send can read a saved lightning address up to a day old; read a fresh kind-0 before paying"
priority: high
needs: decision
---

`startContactSend` (`features/send/lib/startContactSend.ts`) and the profile page's Send read the
recipient's Lightning address from the entity cache (`peekCachedLightningTarget`). The cache is
seeded at launch from the saved profile mirror, and a saved profile is fresh for 24 hours.

Before the cold-start seed kept each profile's fetch time, every saved profile counted as stale
and each row refetched it on mount, which also refreshed the address shortly after launch. Now a
profile saved within the day is not refetched by its row. Within one session the bound was
already 24 hours (a fetched profile was not refetched before then), so the worst case is
unchanged; what changed is that a launch no longer shortens it.

A profile that IS fetched again now replaces the address correctly, removals included: the newest
kind-0 wins. What is missing is a read that insists on freshness at the moment of paying.

Left because it changes the payment entry path (an awaited read before the amount screen, or a
freshness rule on the cached address) and that is the owner's call.

## Done when

Paying a contact uses an address from a kind-0 read within a stated number of minutes, or waits a
bounded time for one, and a test shows a removed address is not paid after a cold start.
