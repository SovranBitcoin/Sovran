title: "NFC auto-pay can read the old unit's balances right after switchUnit"
priority: medium
needs: fix

NFC auto-pay reads `getContext()` right after `switchUnit` (`wallet/src/machine/createMachine.ts`, the payment-request unit switch). The new unit's balances only arrive once React re-runs the `usePaymentFlowMachine` binding effect, and the machine tests use a synchronous context, so a stale read would not be caught.

## Done when

The switch awaits a context whose unit matches, or fails closed; a test with an asynchronous context provider covers it
