A message that is not confirmed yet (15 second mark, or an app restart) is still shown exactly like a failed one,
with "Tap to retry"; if the person retries and the original is then delivered, two delivered copies show and the
peer has the text twice. The "already retried" memory lasts for the app session only (a guard that survives a
relaunch needs a saved value). A native failure whose reason is literally `timeout` or `app_restart` would read as
unconfirmed; Android sends `handshake-timeout`, the iOS vendor source is not in the checkout.

## Done when

Unconfirmed has its own look, or the retry is offered only after a longer wait; the iOS reasons are checked.
