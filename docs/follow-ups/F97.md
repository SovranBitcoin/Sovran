A Lightning receive that a 0.0.1 to 0.0.40 build created, whose invoice was paid and whose ecash was never minted, is detected and recorded (`legacy-ecash-store`, `quotes`, status `paid-unclaimed`) and keeps the old row, but is not minted ([ADR 0032](https://github.com/SovranBitcoin/Sovran/blob/main/app/docs/adr/0032-ecash-from-before-coco-is-claimed-then-the-row-is-removed.md)). Minting it is feasible: a paid NUT-04 quote from that era is not key-locked, so the quote id alone mints it, and Coco can import a quote. It was left out because it is a second way to move money with no fixture from a real mint.


**Looked at on 2026-10-12; no code written, on purpose.** Everything this needs can be read, and none of it can
be run without a mint that holds a paid, unminted quote:

- The claim already finds these quotes and records them: `checkQuote` in `wallet/src/legacy-ecash/claim.ts` writes
  status `paid-unclaimed` and stops there.
- Coco 2.0.0 has the import: `manager.quotes.mint.import({ mintUrl, method: 'bolt11', quote })`
  (`ImportMintQuoteInput`). What it does next is the open part. The app runs Coco's mint watcher with
  `watchExistingPendingQuotesOnStart`, so an imported quote may be minted by the watcher on its own, or may need
  `ops.mint` to be driven; and a quote imported with the wrong snapshot is the kind of thing that watcher retries
  for ever.
- The step to add is one more port on the claim (`wallet.mintPaidQuote`), called for a `paid-unclaimed` record with
  the same attempt limit and delays as the rest, moving the record to a new settled status that `rowVerdict` treats
  as `nothing-to-claim` does. A new status value is read by an older build as `open`, which is safe: it asks the
  mint again and is told the quote is issued.

**Left, with the public test mint (`testnut.cashu.space`, fake payments) and a device or emulator:** build a
0.0.40-shaped `persist:SOVRAN` row holding a quote that the test mint reports as paid and not issued, open this
build over it, and watch what the import does to Coco's quote and history tables before writing the port against
that behaviour. Money moves, so the first run is the specification.

## Done when

The quote is imported into Coco and minted through its mint operation, with the same bounded attempts, and the record moves to a settled state that lets the row go
