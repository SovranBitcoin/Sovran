Not made, each for a stated reason. (1) `HomeFeed` page 0 on `useCachedRead` (`.surgery/pass-3/surveys/feed-social-nostr.md` candidate
2): the shared hook reads on focus, does not cancel the previous tab, cannot be cancelled by load-more and has no
plain re-check, so the move would change what is fetched and when the skeleton shows; the refresh latch (F185) and
the aborted enrichment (F221) stay as pinned. (2) Two owners of the wallet context (`.surgery/pass-3/surveys/wallet.md` candidate 6): the
tracker and the app's `useWalletContext()` disagree, which is itself two defects: the tracker counts proofs that are
reserved for an operation as spendable (the machine reads them for the offline proof check and NFC ranking), and it
builds its payment-method map without the keyset-unit check, so the amount screen can offer a method in a unit the
mint has no keyset for. (3) Pure NFC rules in their own module, the lock-pubkey mirror, the keyring controller, the
album wallpaper owner, the backup answer, the details modal handshake, the mint-info batch reader and selector rows:
each came out longer or needed a behaviour change. (4) The rest of the receive rails: moving the BOLT 12 and onchain
quote hooks up to the screen would create quotes before the hub's entry arrives. Defects seen while cutting and
left: AI recovery after a node repoint picks its model from a balance nothing writes
(`app/features/ai/hooks/useAiSend.ts` about line 697); a failed pull-to-refresh on the home feed clears the paging
cursor and the seen set, so rows can appear twice (pinned as a quirk); `MintDistributionScreen` only checks it is
still mounted, so an older, slower mint-info answer can overwrite a newer one.
