After a failed Lightning-address payment whose npub.cash fallback was dismissed, the machine is on `error` while the
preview is still on screen; Pay is dropped, which the machine's own rule for confirm taps says must not happen. Pass
2 stopped the error from losing its code and message and pinned the rest as a quirk
(`wallet/__tests__/flows/confirm-dead-end.test.ts`). Also left in the payment-request entry: any `operationId` counts
as delivered in `screen-actions/availability.ts`, the rolled-back entry carries the preview id as its `operationId`,
and on the HTTP path `tokenCreated` may overstate a send that was only prepared. `.surgery/pass-2/surveys/wallet.md` C1 to C3.

## Done when

The owner has chosen what Pay does there (retry, reopen the preview, or show the error), and the entry's phase is decoded once.
