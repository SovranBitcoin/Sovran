After a failed Lightning-address payment whose npub.cash fallback was dismissed, the machine is on `error` while the
preview is still on screen; Pay is dropped, which the machine's own rule for confirm taps says must not happen. Pass
2 stopped the error from losing its code and message and pinned the rest as a quirk
(`wallet/__tests__/flows/confirm-dead-end.test.ts`). On the HTTP path of a payment request, `tokenCreated` may
overstate a send that was only prepared.

## Done when

The owner has chosen what Pay does there (retry, reopen the preview, or show the error), with a test.
