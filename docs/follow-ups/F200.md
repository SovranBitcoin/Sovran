priority: high
needs: decision
---

`wallet/src/operations/defaultOperations.ts` (about line 172) rejects when the mint's answer to a melt is lost, although
Coco then shows the melt finalized: the person sees a failed payment that went through. Shown by running, in
`wallet/__tests__/integration/operation-outcome-contract.test.ts`. Related, same file (about lines 153 and 238): the
send and melt "rescue cancel" changed no outcome in any failure case run, because Coco rolls back a refused request
itself and cancel fails on one still executing. A send whose swap result is unknown stays executing with its proofs
reserved. Left because what to show for an unknown outcome is a choice.

## Done when

A melt or send whose outcome is unknown is shown as unknown and settled from Coco's record, never as failed when it was paid.
