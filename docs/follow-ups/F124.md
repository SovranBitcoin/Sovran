title: "An account imported before the wallet-phrase fingerprint existed has none"
priority: low
needs: decision
---

An imported account now records, when it is imported, a fingerprint of the recovery phrase its wallet is derived
from (`walletPhraseFingerprint` on its row in `profile-store`), and both a recovery (`recoverMnemonicSession`) and
the integrity check (`row.imported-wallet-phrase` in `derivationIntegrity.ts`) refuse a different phrase. An account
imported by an earlier build has no fingerprint, so for it a recovery with an unreadable keychain still accepts
any valid phrase and derives it a different wallet.

Recording it for those accounts means writing to the account list the first time such an account opens soundly.
`accountIntegrityStartup.test.tsx` deliberately pins that opening a healthy install written by 0.1.3 rewrites
nothing, so this was not done on 2026-10-12.

**Question for the owner.** Should an existing imported account get its fingerprint on the next healthy launch?

1. **Yes, once (recommended).** The first time the account opens and passes its integrity check, its row gains
   the fingerprint: one added field, written once, never replaced. The start-up test is changed to allow exactly
   that write and nothing else. Every imported account is then protected.
2. **No.** Start-up keeps writing nothing. Only accounts imported from now on are protected; an older one is
   protected if it is removed and imported again.

## Done when

The owner has chosen; if yes, an imported account without a fingerprint gains one on its first sound launch, with
the start-up test naming that single write.
