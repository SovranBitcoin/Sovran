priority: low
needs: fix

`scannedFiles()` in `scripts/followups.mjs` reads `git ls-files -z` with `encoding: 'utf8'`.
After the NUL-framing fix in PR #289, a name holding bytes that are not valid UTF-8 (possible on
Linux, refused by APFS) decodes to U+FFFD. `existsSync` then looks for a different path and drops
the file, so a deleted follow-up cited there passes `check`. This was reproduced on macOS with an
index-only entry; a real Linux file was not tried. `scripts/lib/app-source.mjs` decodes the same
way. It was left out of #289 because that contract named only Unicode, tab and newline names.

Removing the `existsSync` gate, as one reviewer suggested, is not a fix: a tracked file deleted
from the worktree then aborts `check` with ENOENT. Carry Buffer paths from `ls-files -z` through
`existsSync`/`readFileSync`, and decode only for the suffix test and the message.

## Done when

A test that creates a non-UTF-8 name from a Buffer path, stages it without argv and skips where
the filesystem refuses the name fails on the current checker and passes after the fix, in the
ubuntu-latest lint job. The existing twelve cases still pass.
