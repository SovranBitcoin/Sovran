---
id: F117
title: "The Send screen pins sat over its own unit, because the nearby-send hook pins on mount"
priority: medium
needs: investigation
---

`SendScreen` binds the payment machine with the route's `unit`, then mounts `useStartNearbySend`
(`app/features/nearPay/hooks/useStartNearbySend.ts`), which binds it again with `'sat'`. The later binding is the
one in force, so while Send is the top screen the machine's unit is `sat` even when Send was opened for another
unit. This is older than the per-binder pins (commit 3b5485a5b); with them the `sat` pin also comes back when a
screen pushed over Send is popped, where before it fell to the app's active unit. Found by the audit of that
commit on 2026-10-12, by reading and simulation.

Not established: what a `sat` reading does to a flow started from Send in another unit. The machine samples the
unit on every send and every reset (`wallet/src/machine/createMachine.ts`).

Either show the reading is harmless and say so beside the hook, or have the hook pin only for the duration of a
nearby send instead of for as long as it is mounted.

## Done when

A flow started from Send in a non-sat unit is shown to run in that unit, with a test, or the hook no longer pins
while idle.
