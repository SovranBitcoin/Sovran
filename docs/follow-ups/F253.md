`fetchBackedUpMintUrls` in `app/features/settings/lib/recoveryDiscovery.ts` reads a NUT-27 mint
backup (kind 30078, `d` = `mint-list`, NIP-44 self-encrypted, the format cashu.me publishes) for a
wallet seed and returns the mints it lists, through the same URL admission as discovered mints.
`SettingsRecoveryScreen` does not call it yet, so a restore still probes only known and
discovered mints.

Left because wiring it needs two choices and a new relay read: which seed to derive from (the
account's Cashu wallet seed, the bytes Coco restores with, matches cashu.me only when the person
restored the same Cashu mnemonic, not a Sovran root phrase), and which relays to ask during
recovery (the app has no generic "events for this filter" read today; adding one is a new
network path). The codec is in `app/shared/lib/cashu/nut27MintBackup.ts`.

## Done when

With "Search all mints" on, recovery also probes the mints of the newest NUT-27 backup for the
restored seed, shown with the other probe candidates; a test drives the screen with a fake relay
read; the choice of seed and relays is recorded in an ADR.
