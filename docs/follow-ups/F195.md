title: "The native BitChat bridges record a later-version Sovran message's peer as a chat contact"
priority: low
needs: device
---

The JavaScript side keeps every `sovran:` message, whatever its kind or version, out of the BitChat chat store
(`app/shared/providers/BitchatBLEProvider.tsx`, pinned in `app/__tests__/bitchatSovranPrefixSuppression.test.tsx`)
and still hands it to the payment and capability listeners. The two native bridges still match only the version 1
prefixes before recording a recent chat peer, so a `sovran:` message of any other version or kind puts its sender (or,
when sent, its recipient) in the Recent and All chat lists:

- iOS `app/modules/bitchat-module/ios/BitChatBLEBridge.swift:466` (sent) and `:830` (received).
- Android `app/modules/bitchat-module/android/src/main/java/expo/modules/bitchat/BitChatBLEBridge.kt:439` (sent) and
  `:679` (received).

Left because no device was available to check a native change. Nothing sends version 2 today.

A person who types a chat message starting with `sovran:` does not see it in the chat thread. The owner accepted this
on 2026-11-10; it is recorded here, not open work.

## Done when

Both native bridges skip recording a chat peer for the whole `sovran:` namespace, checked on an iPhone and an Android
phone, before any version 2 ships.
