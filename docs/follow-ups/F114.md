title: "Counter reads and the transaction scope sit outside the root write queue"
priority: medium
needs: investigation
---

Found by a Codex audit of the counter-read fix (commit 8f91f004e) on 2026-10-11, each reproduced against an
in-memory delegate; none shown to be reachable through Coco on a device. In `wrapCounterRepository` and
`createSovranCocoRepositories` (`app/shared/lib/cashu/cocoRepositories.ts`):

- `withTransaction` gives each transaction its own `createCounterWriteQueue()`, so a root `setCounter(3)` that has
  read 0 can save 3 after a transaction saved 9, unless the SQLite delegate protects the read and write as one.
- `getCounter` returns its first read when no proof is held, and any positive read, without going through the
  queue, so it can answer 0 or 1 while 9 is saved.
- Two concurrent reads of 0 with a held proof both answer 1.

Settle whether Coco's counter service, the SQLite adapter's `setCounter` statement and expo-sqlite's transaction
isolation already rule these out. Read `../../coco` (the counter service and the sqlite repository) before
changing anything.

## Done when

Each of the three is either shown unreachable, with the reason written beside `wrapCounterRepository`, or fixed
with a test that interleaves the writes.
