`nostr/src/facade/relay/protocol.ts` opens a fresh WebSocket per relay per request (`openWebSocket` at :163 and :220) instead of keeping one connection per relay and multiplexing subscriptions over it, which NIP-01 asks for. The sibling Primal transport makes the same choice but records it — "One socket per request (simple + correct; a pooled multiplexed connection is a later optimization)" — and Primal's cache is not a relay, so only this file is a spec deviation. Its header documents the tier and the REQ/EVENT/EOSE wire but says nothing about socket lifecycle. Flagged by `nip01/single-connection-per-relay` at 0.80.

## Done when

One connection per relay, subscriptions multiplexed by subscription id; reconnect and EOSE-quorum behaviour unchanged; fake-socket tests still cover the demux
