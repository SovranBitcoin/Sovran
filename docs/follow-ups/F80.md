---
id: F80
title: "Removing a profile can strand a payment sent to it that this device has not received"
priority: low
needs: decision
---

Removing a profile cannot see a payment that was sent to it but that this device has not received: the profile is not running, and removal by design does not use its keys or the network (ADR 0030). Such a payment is addressed to a request id that is deleted with the profile, so adding the profile back does not collect it automatically. Removal is not offered in the app at present (F140), so nothing can be stranded this way today; this has to be settled before it returns. The prompt that was taken out said to open the profile first if it may have been paid recently.

**Handed to the owner on 2026-10-12.** The entry already names the two ways; they change what the person sees and
what is kept, so the choice is the owner's.

- **A (recommended). Offer "Open this profile and check for payments first"** in the removal prompt, as a
  button that switches to it. Removal stays offline and never uses the profile's keys.
- **B. Keep the profile's payment request id after removal** so that adding the profile back collects what was
  sent. Something of a removed profile then stays on the phone, which ADR 0030 set out to avoid.
- **C. Say it in words only**, as the prompt that was taken out did.

## Done when

Removal offers to open the profile and sync before deleting, or keeps the request id so a re-added profile can still collect.
