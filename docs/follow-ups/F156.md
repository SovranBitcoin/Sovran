results now have meaningful installation evidence, but no controller-bound receipt. Capture
attestations explicitly say `functionalResult: 'not-established'`; combining green flags
from separate producers would certify a connection they do not establish.

the public CLI on both platforms. It now requires onboarding after confirmation: a regression
through the real player reproduces false passes for blank and wrong destinations against the
old JSON. Existing enabled-button assertions and the seven-second first-step budget remain.
Independent reviewers inspected all five step images and logs on each platform. These are
bounded functional runs, not reliability, upgrade or device-performance certification.

Android's shared session owner uses a fresh AOSP emulator and bundled JavaScript, without
Metro, development timing overrides or permission grants. The run compares installed APK
bytes, build/source identity, exact story hash, session identity and owned cleanup. Provisioning
retains app ownership/SELinux labels and verifies UID 0→2000 with SELinux enforcing before
one launch. The strengthened run is `run-2026-10-16T09-19-34-671Z-211c7c11`; an earlier clean
`c61dbe362` run exercised the original story. Both retain the F142 standing-request warnings
and the adjacent Android recovery-label clipping recorded in F144.

The iOS run is `run-2026-10-16T09-31-21-091Z-220392f0`. Its private wrapper compared the whole
installed payload: paths, types and all file hashes match, with thirteen framework binaries
changing only from mode 0755 to 0644 during installation. Selected and installed full hashes
therefore differ; each stayed unchanged through execution. Both earlier preflight rejections
are preserved with the diagnostic inventory. The wrapper verifies current source and owned
cleanup. The public iOS runner now has an opt-in `--bundled` fresh-story path with selected
build/source and installed-payload checks before launch and after execution; its positive live run on clean `5669fab98` is
`run-2026-10-16T09-49-05-283Z-d5f84863`. All five steps passed with unchanged selected and
installed hashes; independent review inspected screenshots, maps, logs and video metadata,
and the parent inspected one-second video samples. Unflagged iOS stories retain their unbound evidence class. The video decoded and
one-second samples were inspected alongside the step images; continued motion on the final
onboarding screen is recorded. The same F142 warnings remain. No restart-persistence or
physical-device performance claim follows from these results.

The public iOS path also rejected three deliberate faults on that clean revision: changed
installed bytes before launch (zero steps, no hello), changed bytes after the fifth screenshot,

Using actual ADB on owned disposable AOSP emulators, deliberately losing a successful root

## Preserved failures and limits

All attempts remain in ignored app artifacts and private `/tmp/sovran-harness/native-smoke`
and `/tmp/sovran-harness/native-bundled-android` evidence. A later pass does not erase them:

- Earlier Android development runs needed extended startup observation, had an unexplained
  connection failure and missing first-step acknowledgment, and exposed Terms in a map while
  splash covered it. Current-overlay checks prevent the last false pass; an old `splash.gone`
  event cannot clear a remounted overlay. These guards inspect React state, not native compositor
  visibility. The redundant two-second initial map timeout was
  removed. The viewport-offset correction was measured for a full-window Fabric root only.
- A development-run screenshot-write injection reached the final step after all assertions
  passed; it retained failed evidence, returned nonzero and removed the AVD. Earlier attempts
  that never reached the injection remain failures, not clean retries.
- Bundled experiments exposed missing app-data SELinux categories and denied loopback traffic.
  App-data label restoration and the explicitly selected loopback-only test build address
  those causes. Ordinary/test build transitions and production-ID/custom-manifest rejection
  passed a controlled matrix. One earlier unexpected rebuild remains unexplained.
- A real Gradle probe reproduced stale sibling-workspace JavaScript. Explicit rebundling fixes
  that cache gap; before/after source checks reject changed-source build attribution and
  rebuild older caches without source evidence.
- The iOS recorder could accept a playable video after early exit and could hang during
  stop. It now rejects early exit and failed finalization, bounds startup/stop cleanup and
  retains completed step results when recording fails. Real subprocess tests cover these
  paths; simulator fault validation is pending. The separate screen watcher does not
  establish recorder liveness.
- Android still has no continuous recording or pixel-motion measurement. ADR 0033 requires
  recording; screenshots cannot silently waive it. Neither platform's simulator timing is
  physical-device performance evidence. Earlier dirty-build and development runs retain
  their narrower evidence class.

## Remaining integration

Keep the existing story execution owner from ADR 0033. Keep the public iOS binding and its launch/failure checks; an already installed app must
not stand in for the supplied build. Finish recording lifecycle validation on both platforms. Reuse owned session lifecycles and preserve every failed attempt.
Seal exact stories, platforms and log obligations in the controller, then bind native results
to task, generation, invocation, source, binary, session and retained artifact hashes. Route
those artifacts through existing independent inspections and test-oracle reviews.

Reuse capture imports/attestations for visual evidence and `auditFreshMatrixEvidence` for
legacy functional event checks, with exact contract cases/run IDs. Preserve unique legacy
coverage; do not reinterpret capture records as functional passes. Keep performance separate.

## Done when

A disposable, unfunded task runs required cases on both platforms; the controller rejects
stale binaries, wrong sessions, missing cases, failed logs and unread media. Independent
review inspects frames and logs. A performance task compares sealed metrics and thresholds
on the required device/build. Remove each fail-closed guard only with that replacement evidence.
Reject ambiguous repeated actions (the missing-feedback retap was removed in `e0f030943`),
unreviewed oracle changes, unexplained failure-then-pass results, and fixture resets that leave
mint state shared. Every claimed platform needs its own adapter/run evidence.
