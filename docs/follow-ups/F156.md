`harness/src/controller.ts` stops UI and performance work incomplete. Existing story and
legacy scenario results do not attest the installed binary; the capture pipeline does,
but explicitly reports `functionalResult: 'not-established'`. Combining their green flags
would certify a connection the evidence does not contain.

Fresh, unfunded iOS simulators complete the original five-step Terms/Privacy story, including
checks that agreement enables each button. Selected installed payload files match the supplied
build; unique checked sessions, received logs and owned cleanup are retained. Frames show Terms,
Privacy and onboarding. This is smoke evidence, not a controller-bound receipt or complete
installed-payload coverage. Standing-request discard warnings remain.

An Android development diagnostic completes the same interactions after reading the existing
React DevTools root registry and correcting Fabric's viewport offset before physical taps.
Maps and screenshots confirm the agreement value changes and buttons become enabled. That
measurement covers this full-window root, not arbitrary embedded React surfaces. The diagnostic
allows a separate 60-second startup observation; it does not pass the original seven-second
startup requirement. Earlier attempts include an unexplained connection failure and a map
that exposed Terms while a splash still covered it. The player now checks the currently mounted
overlay before targeted actions, typing and visual assertions; a historical `splash.gone` event
cannot clear a later overlay. Regression tests cover remounts and forced settling. Fresh iOS
and Android runs show the legal pages uncovered, but native compositor visibility is separate.
The optional initial map capture also imposed a separate two-second startup timeout; per-step
maps and final diagnostics replace it. Keep every attempt and diagnose failure-then-pass results.

Android checks installed APK bytes, session identity, source stability and owned cleanup, and
retains recent device logs and a final screen before teardown, including connection failures.
This lane uses extended development timings, pregranted location, and no video/pixel-motion
measurement; it is not the bundled lane required by ADR 0033 or device-performance evidence.
The first build was rejected for fingerprint drift; a controlled second build passed after
Gradle manifest normalization. Attempts and source/build records remain private. A deliberate
final-step screenshot write failure was reached after all five UI assertions passed: the runner
retained those results, final diagnostics and a failed report, exited nonzero, and removed its
owned AVD. Startup in that diagnostic took 17 seconds. Earlier attempts failed before reaching
the injection, including a missing first-step acknowledgement; they remain unexplained failures,
not clean retries. The acknowledgement failure retained its blank startup screen and device logs.

A private Android bundled experiment on 2026-10-16 passed the unchanged five-step story
on a fresh AOSP API 36 emulator, without Metro or timing overrides. Frames independently
show agreement toggles enabling buttons, Terms to Privacy, then onboarding. Installed APK
bytes and session identity matched; the owned device was removed. Earlier attempts exposed
missing app-data SELinux categories and a denied loopback WebSocket. Android's app-data
`restorecon` flag fixed the labels; an explicitly selected, loopback-only test build policy
allowed the connection. All attempts remain under `/tmp/sovran-harness/native-bundled-android`.
The passing run retained three `creq.standing.recorded_discarded` warnings (`unit_mismatch`),
not a clean log. This dirty-build experiment does not cover later environment sanitization,
the public Android story CLI, failure-safe unrooting, continuous video, or controller receipt
binding. A separate build matrix verifies ordinary/test cache transitions, removal of the
loopback exception on ordinary builds, and rejection of production IDs or existing Release
manifests. One earlier cache experiment rebuilt unexpectedly; its cause remains unverified.
The controlled matrix held source fixed and passed, without erasing that failed attempt.
The commit audit also found stale workspace bundling and post-build attribution races.
A real Gradle probe reproduced the first; forced bundle generation includes the changed
workspace bytes. Source comparisons before and after compilation reject commit or dirty-file
drift, and older bundled caches without that evidence are rebuilt. The native guard remains closed.

The Android story CLI now selects a bundled lane through the shared session owner,
with fresh AOSP allocation, installed-byte comparison, owned-device checks, app-data note
provisioning and verified unrooting before one launch. Raw privilege and SELinux observations
are retained. Source is compared to the selected build before provisioning and after the
story. Scripted transport tests cover ambiguous root replies, cancellation, failed writes,
failed unrooting and combined failures; removing restoration makes those tests fail.
On clean commit `c61dbe362`, the public bundled CLI passed the unchanged original story.
Independent review inspected all five frames, maps, logs, matching installed APK bytes,
source identity, UID 0→2000 and enforcing SELinux observations, and verified AVD removal.
Separate real-transport injections lost the root response and sent SIGTERM after rooting;
both prevented launch, restored UID 2000/Enforcing and removed their owned devices.
These are deliberate negative tests, not observed random failures. The successful story
still has the standing-request warnings tracked in F142 and an adjacent clipped onboarding
recovery label recorded in F144. It is one functional run, with no video, restart-persistence,
performance or controller attestation. Review also found that absence-only final assertions
could accept a blank or wrong page: the story now requires onboarding, with both forbidden
outcomes reproduced against the old JSON. The strengthened story still needs a native run.

Reuse `app/e2e/capture/refresh.ts` capture attestations and
`app/e2e/capture/import.ts` (`importCaptureRun`, with an explicit private `libraryDir`) for
visual evidence. Reuse `auditFreshMatrixEvidence` for functional raw-event checks, selecting
the contract's exact cases and run IDs rather than its CLI's fixed denominator.
Use the story execution owner in ADR 0033 for new functional integration; retain legacy
scenario evidence where it still provides unique coverage. Add producer-side installed-binary identity to functional runs and bind it to the controller's
source, invocation, session and evidence hashes. Keep device performance distinct from
simulator timings. This needs native integration and device evidence, not another report format.

## Done when

A disposable, unfunded task runs required cases on both platforms; the controller rejects
stale binaries, wrong sessions, missing cases, failed logs and unread media. Independent
review inspects frames and logs. A performance task compares sealed metrics and thresholds
on the required device/build. Then remove the fail-closed native guard with regression tests.
Correctness and reliability of the evidence producer are checked too: reject ambiguous
repeated actions (the missing-feedback retap was removed in `e0f030943`), unreviewed test-oracle changes,
unexplained failure-then-pass results, and fixture resets that leave mint state shared.
Every claimed platform has actual adapter/run evidence; an iOS story does not certify Android.
