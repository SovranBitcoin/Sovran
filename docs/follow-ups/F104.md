id: F104
title: "Profile removal deletes the wallet database before the forget-record is known to be saved"
status: open
priority: medium
needs: fix
---

The `wallet database` step in `app/shared/lib/profile/profileRemovalStorage.ts` (and the same order in
`profileSessionOrchestrator.ts`) calls `forgetWalletDatabases`, a store setter that does not wait for its save, and
then deletes the files. If that save is dropped and the removal is interrupted before the profile list is rewritten,
the next launch still lists the database, finds it missing, and shows a loss prompt for an account the person chose
to remove. The profile-list step in the same file does await its write.

Found by a Codex trial audit of commit 4003e17e4 on 2026-10-11 by reading the source; not reproduced on a device.

## Done when

The forget is confirmed on disk before the files are deleted, with a test that fails the save and interrupts.
