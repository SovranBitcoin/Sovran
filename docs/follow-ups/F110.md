title: "Nothing fails when a secure key, raw storage key, database name or storage library version changes"
priority: medium
needs: test
---

The upgrade tests are driven by the store registry, so a new persisted store turns three tests red. A new
SecureStore key, a new AsyncStorage key written outside a store (Whitenoise, `routstr-sdk:*`, the nearby-payment
journal, the pairing intent), a new database name, or a new version of expo-secure-store, expo-sqlite or
AsyncStorage turns nothing red. `releasedPersistedSurface.test.ts` only checks that the eight key names 0.1.3 used
still exist. `.agents/skills/persistence-release-safety/surface.sh` already has the patterns that find these.

## Done when

A test compares the secure keys, raw storage keys, database names and storage library versions found in the source
with a recorded list, and fails with an instruction when they differ.
