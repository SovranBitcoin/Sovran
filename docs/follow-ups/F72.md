title: "Nothing reads back :unreadable store copies; large stores need a stated policy"
priority: low
needs: decision

A store that failed to load used to have its blob replaced by its next write. Closed on 2026-10-09 by `app/shared/lib/persist/preserveUnreadable.ts`, applied to every store through `persistConfig`: a blob that was read but rejected is copied to `<store>:unreadable` before the first overwrite, and a blob that could not be read is not overwritten (`persistUnreadableGuard.test.ts`). `routstr-store` keeps its own rules; query caches and the map cache opt out and are replaced as before. Still open: nothing reads the copies back yet; a durable store whose row is too large for Android to read (`nostr-metadata-cache` and `own-content-store` can grow that far) stops saving instead of being replaced, and may want the cache policy; during an in-process switch a copy that is waiting is not counted by the switch's write drain.

**Handed to the owner on 2026-10-12.** Both halves are policy.

1. **When should a kept `:unreadable` copy be read back?**
   - **A (recommended). Never automatically; offer it from Settings, Storage.** A row there says "Sovran kept data
     it could not read from `<store>`" with Export and Delete. Nothing is merged without the person asking.
   - **B. On the first launch of each release, try the current schema on every copy** and merge what parses.
     Hands-off, but a merge of old data over newer data can itself lose something.
   - **C. Keep the copies and do nothing** until a specific loss needs one.
2. **`nostr-metadata-cache` and `own-content-store` can grow past what Android can read back in one row**, and
   then stop saving. Should they follow the cache rule (a bad or oversized row is replaced, because it can be
   fetched again) or move to a file like the map cache? Recommended: the cache rule for `nostr-metadata-cache`,
   a file for `own-content-store`.

## Done when

A recovery path reads `:unreadable` copies after a release that can parse them; each large store has a stated policy.
