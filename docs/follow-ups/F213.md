If the app dies after the mint swap but before the queue entry is marked done, the next run finds the token spent,
shows a red "Token was already redeemed" toast for money that did arrive, and the history row has no sender.
`.surgery/pass-2/surveys/messaging-signer-ai.md` D4 and candidate 2 (traced). Pinned as a quirk in `app/__tests__/nutDropInterruptedRedeem.test.ts`. The wallet could tell: each finished receive in
Coco's history carries the proofs it received. Open choices: how far back to search, what to do while Coco's own
crash recovery has not finished that receive, whether a token received by hand counts, and how the toast is
confirmed (no wallet event fires on a late match). Left because telling "spent by us" from "spent by someone
else" needs a check against the wallet's own history that was not designed in this pass.

## Done when

A drop whose proofs this wallet already holds is marked redeemed quietly, with its sender, and a test kills the run between swap and mark.
