Async cancellation and single-flight discipline is uneven across shipping code. `conventions-async-tests` returns **61 findings outside tests and tooling**, clustered as: `signal-unchecked-after-await` (17) — an `AbortSignal` checked before an await but not after, so a superseded request still writes; `unbounded-fanout` (10) — `Promise.all` over a caller-sized list with no concurrency cap; `sleep-ignores-cancel` (9) — bare `await new Promise(r => setTimeout(r, …))` that no abort can interrupt, including three in `sovranPaymentConfig.ts` (the legacy auto-redeem reconciliation poll has since been replaced with an operation-bound lookup); `guard-released-on-every-path` (8) and `guard-before-await` (7) — single-flight guards whose release is not on every path, including `wallet/src/machine/createMachine.ts:1501`; plus `non-error-throwables` (6), `status-before-body` (6) and `url-unencoded-interpolation` (4). Individually small; together they are the reason a superseded search, a stale profile sync or an abandoned poll can still land.

## Done when

Cancellation checked after every await on a path that writes state; fan-out bounded; sleeps take a signal; each single-flight guard released in a `finally`; the rule family returns only tooling and test hits
