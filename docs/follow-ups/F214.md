One answer's state is split across the saved message, the send hook, the live-text buffer, an error map and a
truncation map, and every write goes to whichever conversation is current. Switching or starting a conversation
mid-stream loses the answer and leaves the question `pending` in saved data; an older stream's cleanup wipes a newer
stream's text; leaving the screen mid-answer deletes the answer, which a comment in the code says must never happen.
`.surgery/pass-2/surveys/messaging-signer-ai.md` candidate 3 and D5 to D7 (traced). Left because the repair is the conversion of the
answer lifecycle, which is a pass 2 proposal awaiting approval.

## Done when

An answer belongs to the conversation and turn that asked for it from start to finish, with tests for a switch, an overlap and an unmount mid-stream.
