id: F181
title: "A receive or mint lookup can adopt another operation's row when its own has not been saved yet"
priority: medium
needs: decision
---

`findReceiveHistoryEntryForOperation` and the mint-quote poll in `wallet/src/operations/receiveOperations.ts` now
prefer the exact operation or quote, but still fall back to any row that is new since the snapshot. If another
receive from the same mint is saved first, the lookup returns it without waiting for its own; a failed snapshot makes
every existing row eligible. Left because dropping the fallback changes what happens when Coco's row id cannot be
matched, which the fallback exists for.

## Done when

The lookup never returns a row that names a different operation or quote.
