priority: medium
needs: fix

Provider initialisation was not tied to the mount that started it. Closed on 2026-10-09 for startup and reset: `CocoManager.cleanup()` waits for an initialise in flight and clears only the credentials nobody restaged; an initialise reads its whole identity before its first await and discards its work when a delete-all happened meanwhile; delete-all waits for an initialise, closes the database before deleting it and reports a database it could not remove; `CocoProvider` and `NostrKeysProvider` ignore results that arrive after unmount (`cocoCleanupDuringInit.test.ts`). Still open, in-process switch only: the switch checks readiness before awaiting its disk guard, so wallet background work (NPC sync) can begin in that gap and later read the next account's signer through the live statics while holding the previous account's manager; an initialise or cleanup that never settles blocks every later open. Must be closed before the in-process switch becomes the default.

## Done when

Background work is bound to the identity it started with and drained before the account flips, with a test.
