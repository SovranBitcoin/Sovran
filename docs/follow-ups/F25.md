Seven send/receive routes take a JSON-encoded Colada entry (schema allows 64,000 characters) as a route param instead of an identifier. Keep the entry in the payment machine context or a runtime store keyed by id.

**Not started on 2026-10-12.** Replacing a JSON entry in seven route params with an id changes how each of those
screens is entered: from the flow, on back-navigation, on re-entry and from a deep link. The store that holds
the entry by id and its unit tests can be written without a phone; whether each of the seven routes still opens,
goes back and re-enters correctly on both platforms cannot, and the native scenarios that cover them have to be
run. Do one route at a time, each with its scenario.

## Done when

Route params are identifiers; back-navigation, re-entry and deep-link entry keep working
