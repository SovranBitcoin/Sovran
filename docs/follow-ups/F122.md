---
id: F122
title: "The app can publish an event its own reader then leaves out"
priority: low
needs: fix
---

Events read from the backend, a relay or the Primal cache are refused past the ceilings in `NOSTR_EVENT_LIMITS`
(`nostr/src/schemas.ts`). Nothing holds what the app publishes to the same ceilings. A repost carries the whole
original as JSON (`app/features/feed/hooks/useNostrEngagement.ts`), so an original just under the content ceiling
makes a repost over it: relays may accept it and the app will not show it. The same holds for any long-form or list
event the app writes that is larger than it would read. Found in review on 2026-10-12 and left because the two
fixes pull in different directions and neither has a measured case behind it.

## Done when

Either every publish path refuses an event `NOSTR_EVENT_LIMITS` would reject, with a message the person can act
on, or the read ceiling for a kind that embeds another event allows for the embedded one; a test publishes the
largest event the app can build and reads it back.
