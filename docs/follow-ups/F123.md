---
id: F123
title: "A wallet initialise or teardown that never settles blocks every later open"
priority: medium
needs: decision
---

`CocoManager.cleanup()` waits for an initialise in flight (`pendingInit`) with no time limit, and `initialize()`
waits for a teardown in flight (`pendingCleanup`) the same way (`app/shared/lib/cashu/manager.ts`). If either never
settles (a database open or close that hangs natively), every later open of the wallet waits on it for the life of
the process: the wallet stays on its loading screen until the app is restarted. Carried over on 2026-10-12
from an entry whose other half (background start-up running on into the next account) is fixed. Left because the
safe thing to do when the wait runs out is not obvious: going on while a database handle may still be open is how
a wallet database gets opened twice.


**Looked at again on 2026-10-12.** The mechanics are small: bound the two waits and, when one runs out, fail the
open so `CocoProvider` shows the failure screen it already has (with its retry) instead of a spinner; never open a
second database handle. What cannot be settled by reading is the time. An open is also how a wallet database is
migrated, and a first open after an upgrade copies a backup and runs every migration; on a slow phone with a large
wallet nobody has measured how long that takes. Too short a limit shows a failure screen over a migration that is
going fine.

**Question for the owner.** How long may a wallet open or close run before the person is shown the failure screen?

1. **Two minutes (recommended).** Far longer than any open seen so far (seconds), short enough that a hung phone
   is not left on a spinner. The screen says the wallet is taking too long and offers Try again and Restart; a
   migration that was merely slow finishes in the background and Try again then succeeds.
2. **Thirty seconds.** Closer to how long people wait. A migration slower than that shows the failure screen
   while it is still working; Try again joins it. Needs a measured migration time on an old phone first.
3. **No limit.** Leave it as it is; a hung open is rare and a restart clears it. This entry is closed as decided.

## Done when

An initialise or teardown that does not settle within a stated time ends in a state the person can act on (the
wallet's failure screen with a restart, not a spinner), and a later open does not wait on it; a test parks each
and shows the next open resolving or failing in bounded time.
