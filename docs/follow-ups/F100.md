---
id: F100
title: "Upgrades from 0.0.61 or earlier are read as not onboarded and offered a restore"
priority: medium
needs: fix
---

An install upgraded from 0.0.61 or earlier has no `hasSeenOnboarding` in its settings (those releases had only the accepted terms), so this build reads it as false. `stampSeedCreatedForExistingUsers` then leaves `wallet-lifecycle` unstamped (`seedCreatedAt: null`, `restoreStatus: 'unknown'`), and from reading `AppGate` the install is taken for a reinstall: onboarding is skipped and a restore is offered. Money and keys are unaffected. Pinned by the `that onboarding was seen` known gap of the E12 to E14 release fixtures; what the restore gate shows has not been seen on a device.

## Done when

Accepted terms count as onboarding seen for an upgrading install (or the reinstall path is confirmed on a device to be the intended one, in writing), and the known gaps are removed.
