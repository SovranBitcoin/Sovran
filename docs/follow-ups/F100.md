needs: device

An install upgraded from 0.0.61 or earlier had no `hasSeenOnboarding` in its settings, was read as not onboarded, and was taken for a reinstall and offered a restore. Fixed in tests on 2026-10-11: the settings store's `migrate` and `stampSeedCreatedForExistingUsers` both read accepted terms without the flag as onboarding seen, and `migrateThenLoad` (`app/shared/lib/migrations/migrateThenLoad.ts`) loads again any required store whose row a migration wrote, so the stamp is no longer overwritten by defaults. Fixtures E7 to E15 check the flag and `restoreStatus: 'not-needed'`; `app/__tests__/migrateThenLoad.test.ts` covers the reinstall.

Two things are left. An install that already passed through 0.0.63 to 0.1.3 unstamped has the stamp's migration id recorded and was sent to the restore screen by those releases; if it never finished, it is still asked, because nothing on disk tells it from a reinstall that stopped at the same point. And none of this has been seen on a device.

## Done when

An upgrade from a 0.0.61 or earlier build on a device opens with no onboarding and no restore prompt; and the unfinished-restore case is either told apart or accepted in writing.
