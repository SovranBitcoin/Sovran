The NIP-46 pairing secret travels in navigation state: `+native-intent` rewrites a `nostrconnect://` URI into `/(signer-flow)/connect?uri=…`, and that URI embeds the bearer secret. Hold the validated URI in a runtime-only store and route with no param or an opaque nonce.

**Code done on 2026-10-11; a device run is what is left.** `+native-intent` now keeps the link in memory
(`app/features/nostrSigner/lib/pendingPairingUri.ts`) and routes to `/(signer-flow)/connect?ticket=<n>`; the route
redeems the ticket once and no longer reads a link from a param (`nip46PairingEntry.test.ts`,
`signerConnectRoute.test.tsx`). Not run: `wallet.deeplink.nostrconnect` on iPhone and Android, warm and from a
cold start. On a cold start the thing to confirm is that the link held by `+native-intent` is still there when
the connect route mounts.

## Done when

No pairing secret in route params or navigation history; cold-start and warm deep-link journeys pass on both platforms
