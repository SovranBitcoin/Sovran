title: "The persistence scan and map miss native BitChat storage, keys passed as constants and files"
priority: medium
needs: fix
---

`persistenceSurface.test.ts` records an AsyncStorage key only when the call has a string literal, a secure key only
from `STORAGE_KEYS`, and a database only with a `.db` suffix; it skips native code and files. So a new
`nip46_pending_pairing`-style secure key, the Whitenoise prefixes, `nostr-<i>`, the BitChat keychain items and
preferences on both platforms (identity keys, peer summaries, vendor favorites), and files on disk can change without
turning a test red. The BitChat vendor sources are not in this checkout, so their keys are not listed anywhere.
`releaseFixturesCompleteness` walks the store registry only. The map's corrections of 2026-11-10 list what was found
by hand.

## Done when

The scan lists constant-named keys, every secure key, the Nostr cache database and native storage, and the completeness test asks for a fixture row or a reason for each.
