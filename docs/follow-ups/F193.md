0.1.3 sends the whole encoded request as the payload's `id` (`wallet/src/operations/defaultOperations.ts` at
`d9ad12c4b`, about line 1821); the request's own id is what Coco matches on. Today's receiver hands the payload to
Coco unchanged, Coco refuses it ("No active payment request found"), and
`app/shared/lib/cashu/paymentRequestNostrTransport.ts` treats that as retryable, so the same wrap is unwrapped and
refused on every poll. The sender's ecash stays in a pending send until they reclaim it. 0.1.3 receivers refuse it too.
Today's sender is fixed; the receiver is not. Pinned in `app/__tests__/paymentRequestReleasedPayer.test.ts` against
the real Coco. Left because it changes what the receiver accepts on the wire. Tried in a throwaway copy: replacing an
`id` that is itself a request with that request's id makes the claim go through.

## Done when

A payment from a 0.1.3 sender is claimed, and a payload Coco refuses for good is not offered again on every poll.
