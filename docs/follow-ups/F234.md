Toast: the payment flow's callbacks carry no payment id, so two payments from one flow with the same type, mint,
amount and unit cannot be told apart; receive-ecash toasts are still matched by mint and amount; a held result that
was the toast's own but was never bound would show as a second success. Restore status
(`app/shared/stores/global/walletRestorePhase.ts`): the readers disagree by design of the old code and now say so:
the prompt rules hold only for `pending` while the prompt host also holds for `failed`; with no seed the gate keeps
`failed` on the recovery screen but opens the wallet for `in-progress` while minting keeps waiting; `failed` has no
writer anywhere in the repo's history. White Noise: one send guard is shared across peers, so a send that never
settles for one peer silently drops a send to the next.

## Done when

Flow callbacks name their payment; the owner has ruled on the restore-status disagreements; the White Noise guard is per conversation.
