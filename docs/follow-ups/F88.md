id: F88
title: "A schema-rejected routstr-store silently stops saving for the session"
priority: low
needs: device
---

When `routstr-store` is rejected by its schema it now keeps the stored key safe by saving nothing for the rest of the session, so chats started in that session are lost on restart, with one log line and no message. It needs a blob no release is known to have written.


**Looked at on 2026-10-12.** Keeping the fields that parse is not safe for this store: its fields refer to each
other (`currentSessionId` into `sessions`, the key and the recovery records in the secure vault), which is why its
merge is all-or-nothing. That leaves the second half of "Done when": show that saving is off. Where the state is:
`saveOnlyAfterAcceptedLoad` in `app/shared/stores/profile/routstrStore.ts` holds `load === 'rejected'` and drops
every save after it; nothing outside that function can see it.

**Left, with a phone or emulator, because it is something on screen:** give the store a session-only `savingOff`
field (not in `partialize`) set when a load ends rejected or fails, and show the shared `Notice`
(`@/shared/ui/composed/Notice`, `status="warning"`) on `AiChatScreen` while it is true, saying that chats from this
session will not be kept and the saved ones were left untouched. The chat screen draws its own header and
keyboard-lifted list, so the notice has to be placed and looked at running on both platforms, beside
`ProviderInfoScreen`, which already uses it. To reach the state on a device, write a `routstr-store` row with
`sessions` set to a string and open the AI tab.

## Done when

The store keeps the fields that parse and tells the user what was dropped, or shows that saving is off.
