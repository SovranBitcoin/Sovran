id: F99
title: "routstr-store fails to load on the first launch of an install with no account list"
status: open
priority: low
needs: fix
---

On the first launch of an install with no account list (an upgrade from 0.0.1 to 0.0.56, and possibly a new install), `routstr-store` cannot load if its module is evaluated before the keys provider adds account 0: `captureProfileStorageOwner` throws `Profile storage is not ready`, nothing loads the store again in that session, and it refuses to save until the next launch. The stored key and chats are untouched and load on the second launch. Seen in `app/__tests__/releaseFixtures.test.ts`, which evaluates every store module at startup; whether the bundle does so before the keys are ready is not confirmed on a device.

## Done when

The store loads once account 0 has its row (a reload after `addProfile`, or a wait in the adapter), and the `it.failing` case in `releaseFixtures.test.ts` is removed.
