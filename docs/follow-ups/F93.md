Done in code and unit tests: an account whose saved identity does not follow from the recovery phrase (or, for an imported account, from its stored key) stops on a critical screen with nothing written or deleted, at startup (the full check, before the account is ready), on switch, on create, on import and before a wallet opens ([derivation.md](../architecture/persistence/derivation.md)). Still open: (1) a person stopped there cannot spend or export the ecash already in that account's database, which matters for the one state seen in the field (a 0.1.3 Android backup restore without the keychain) when they no longer have the original phrase; (2) nothing has run on a device. After Wave 0 replaced `react-native-quick-crypto` with `expo-crypto`, `globalThis.crypto.subtle` is absent on Hermes so cold-start verification currently runs `@scure/bip39` `mnemonicToSeedSync` on the JS thread (root phrase + wallet phrase when a current seed cache exists). Measure real cold-start duration on iOS and Android hardware; if it causes a noticeable launch pause, back `stretchPhraseNative` with a minimal native PBKDF2-SHA512 helper (`CommonCrypto` / `SecretKeyFactory`) rather than re-adding `react-native-quick-crypto`.

## Done when

A decision on a read-only way to move that ecash out, built if wanted; and one launch on each platform that confirms the native stretch is used and times the check, plus one with a forced mismatch.
