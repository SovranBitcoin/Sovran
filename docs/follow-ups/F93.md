Done in code and unit tests: an account whose saved identity does not follow from the recovery phrase (or, for an imported account, from its stored key) stops on a critical screen with nothing written or deleted, at startup (the full check, before the account is ready), on switch, on create, on import and before a wallet opens ([derivation.md](../architecture/persistence/derivation.md)). Still open: (1) a person stopped there cannot spend or export the ecash already in that account's database, which matters for the one state seen in the field (a 0.1.3 Android backup restore without the keychain) when they no longer have the original phrase; (2) nothing has run on a device. The startup check stretches the phrase and the wallet phrase with the platform's PBKDF2 (`crypto.subtle` from react-native-quick-crypto), which is only exercised under Node. If that call is missing or fails on a phone, every cold start pays two JavaScript stretches on the JS thread instead, seconds each on an old device.

## Done when

A decision on a read-only way to move that ecash out, built if wanted; and one launch on each platform that confirms the native stretch is used and times the check, plus one with a forced mismatch.
