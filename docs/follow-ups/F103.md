---
id: F103
title: "The wallet counter read can report 1 while a higher counter is saved"
status: open
priority: high
needs: fix
---

`wrapCounterRepository.getCounter` in `app/shared/lib/cashu/cocoRepositories.ts` handles a stored counter of 0 with a
held proof by queueing a write of 1 and returning the literal 1. The queued task rereads the row and leaves a higher
value alone, but the caller has already been told 1. If another write raised the counter between the first read and
the queued one, the wallet derives from an index below the saved high-water mark, which is the reuse the wrapper
exists to prevent.

Found by a Codex trial audit of commit 4835e8bd0 on 2026-10-11, which ran the function with the real queue in memory
and got `returned: 1, persisted: 9`. Read in the source and confirmed; whether any real call order reaches it is not
established.

## Done when

`getCounter` returns the value the queued task settled on, with a test that interleaves a higher write.
