No app-wide i18n yet. Chosen direction: one locale service, Lingui with build-time compiled ICU catalogs, `expo-localization` for device preferences, wallet copy integrated through its existing resolver. Verify versions and `Intl` support on Hermes first.

One thing the locale service has to settle, moved here from the date entry on 2026-10-12: `resolveLocale` in
`app/shared/lib/date.ts` reads the saved language `'en'` as "not chosen" and uses the phone's locale, because
`'en'` is also the default every install has saved. Nothing in the app sets the language today, so it changes
nothing yet; once a language picker exists, someone who picks English on a German phone would still get German
dates unless the default becomes a value that means "follow the phone".

**Handed to the owner on 2026-10-12; no code changed.** The chosen direction adds dependencies (Lingui and its
build step, `expo-localization`), which an agent does not add on its own, and it changes what every person sees.
Before any of it:

- **A (recommended). Confirm the direction and the first languages**, and that Lingui's build-time catalogs are
  acceptable in the Metro and EAS build. Then this becomes a sequence of fix entries: the locale service, the
  catalogs, wallet copy through its resolver, native strings, and the pseudolocale, right-to-left and large-text
  checks.
- **B. English only for now.** Close this and reopen it when a second language is wanted. The date module already
  follows the phone's region.
