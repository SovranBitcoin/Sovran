---
id: F173
title: "Blossom image URLs carry no file extension, so extension-sniffing clients show a bare link"
priority: low
needs: investigation
---

`uploadMedia` in `app/shared/lib/nostr/media/mediaUpload.ts` puts the Blossom server's
`descriptor.url` into the note unchanged, so the note holds a bare hash URL. Sovran's own feed
renders it, because the note also carries a NIP-92 `imeta` tag with the mime type
(`mediaKindForMime`). Clients that decide what to render from the file extension, such as
njump, show a plain link instead of the image. PR #221 fixed this in June by adding the
extension that matches the mime type (Blossom serves `<sha256>.<ext>` the same as
`<sha256>`). It was closed in November 2026 because it was 1,900 commits behind and predated
the monorepo layout. `blossomSha256FromUrl` already accepts URLs with an extension, so redoing
it on main is small.

## Done when

A current njump (or another client that sniffs extensions) still shows a bare link for a
Sovran image post, and after the change it shows the image. Or the first check shows it
renders correctly already, and this entry is deleted.
