title: "amountToNumber exists five times with four different answers for bad input"
priority: high
needs: fix

`amountToNumber` exists **five** times with four different answers for bad input, and this entry named one of them. `app/shared/lib/cashu/amount.ts` (24 importers) and `wallet/src/amount.ts` return `NaN` for an unparseable string with a warn/debug log; `wallet/src/balance/breakdown.ts` and `wallet/src/history/timeline/context.ts` silently return `0`; `app/e2e/funded-runtime/payment-request-payer.ts` throws — the only one that refuses to invent a number. All five map `null` to `0`, collapsing unknown into zero. `toSafeSatAmount` separately truncates. Converge on one implementation that separates display coercion from validation, taking the e2e version's refusal as the model, and keep `amountToNumberOrUndefined` for the genuinely-unknown case.

## Done when

One `amountToNumber`; unparseable and unsafe input cannot become `0` or `NaN` on a path that authorizes a spend; unknown distinguishable from zero; callers classified
