title: "A Bluetooth message marked failed by the 15 second timer stays failed after it is delivered"
priority: medium
needs: decision
---

`bitchat-dm-messages-store` treats `failed` as final, so a late delivered report is ignored and the person is offered
a retry for a message that arrived; retrying sends it twice. A restart also turns `sent` into `failed`. The current
test pins the rule as intended. State table in `.surgery/pass-2/surveys/messaging-signer-ai.md` candidate 1 and D1 (run). Also left: the
"already retried" memory added in pass 2 lasts for the app session only, because a guard that survives a relaunch
needs a new saved field. Left because it changes the meaning of a saved status.

## Done when

The owner has ruled whether a timeout is final; if not, a saved `failed` with reason `timeout` or `app_restart` reads as unconfirmed and a later delivered report wins, with the saved shape unchanged.
