id: F259
title: "Nostr data path: defects from the data audit left after batching, merge and inbox work"
priority: medium
needs: fix
---

The Nostr data audit listed 24 defects. Profile batching, the shared Primal socket, the
newest-event merge, the cold-start seed, the gift-wrap dedupe and resume, reconnect backoff, the
payment inbox, search hits, the following count and the person-row height were done. These were
left, each because it is its own change:

- **Three socket stacks remain.** `NostrClient` (`nostr/src/client/relayPool.ts`) still holds its
  own socket to each relay beside the facade's shared connection
  (`app/shared/lib/nostr/relayConnection.ts`), and `SimplePool` is still built per lookup in
  `sendDirectMessage.ts` and `nutzapProfileDiscovery.ts`. Folding them into one pool changes how
  publishes are acknowledged and was not a contained change.
- **Reconnect triggers are not debounced.** `useOwnRelayListSync`, `useFollowSync` and
  `subscribeEveryRelay` in `useOwnEventsSync.ts` re-ask on every `relay:connect`. Backoff now
  bounds how often that fires; the triggers themselves are unchanged.
- **The list hook keeps its own fetch state.** `useNostrProfileMetadataMany` still tracks
  `attempted`, `pendingPubkeys` and `settledPubkeys` per instance. Only the single-profile hook
  was moved onto the cache's pending and miss state.
- **Every NIP-05 row has its own timers and AppState listener** (`useNip05Verification.ts`), and
  verified results are not saved.
- **Kind 10050 and 10019 lookups are uncached and unbatched** (`dmRelayDiscovery.ts`,
  `publishGiftWrappedDM.ts`, `nutzapProfileDiscovery.ts`), and misses are not remembered.
- **No outbox reads.** Profiles are read from the five default relays only, never from the
  subject's own NIP-65 write relays, so someone who publishes elsewhere looks absent.
- **Profile stats and Vertex scores are memory-only with no expiry**, and profile misses are
  memory-only too: both start blank on every launch.
- **`useOwnEventsSync` sets state once per event**, and `buildNostrDataLayer()` still runs in the
  render path of `useProfileRecordsMany`.
- **The gift-wrap read window is per session.** The newest wrap date read is not saved, so each
  launch reads the whole inbox once. Saving it needs a new persisted value.
- **`relay.nostr.band` is in both default relay sets** (`outbox/defaults.ts`, `shared/ndk.ts`).
  Nothing in the code says it is retired, so it was kept; whether it still answers was not
  checked. Removing it changes where payment requests tell payers to deliver.
- **Documents describe tiers that are gone.** ADR 0003 and ADR 0006 still name a nagg tier and
  the NDK pool.

## Done when

Each item above is either fixed with a test that fails on the old code, or has its own entry
saying why it stays.
