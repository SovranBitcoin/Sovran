`Pressable` now fires a light impact on press-in by default, `Button` picks one from its variant,
list rows (`ListRow`, `ContactRow`) tick on release (`ROW_HAPTICS`), and `popup()` /
`StatusToast` fire the outcome notification. This was verified by unit tests only, never felt on
a phone. Still open:

- Pull-to-refresh (`RefreshControl` in `SettingsNetworkScreen`, `SettingsStorageScreen`,
  `PullToAiRefreshControl`, `List onRefresh` in `MintChangesScreen`) fires nothing.
- `Sheet` and `ToastHost` swipe-to-dismiss have no tick at the dismiss threshold.
- Header back/close (`ScreenHeaderAction`, `HeaderGlassCircle`) now taps lightly like every
  other button; the haptics audit suggested none for navigation chrome. The owner's call.
- The design-system `AccountRowFixture` and `SettingsToggleItem` specimens still fire, since
  those wrappers do not forward `haptics`.
- An ecash receive on the Nut Drop radar that is not a strike (a DM token redeemed while the
  radar is up) fires no haptic: the toast leaves it to the ceremony, which only plays for strikes.
- `Colada`'s `clipboardAdapter.writeText` copies without a haptic.

## Done when

Each control family has been felt on an iOS and an Android device, and every point above is
either implemented or recorded as deliberately silent.
