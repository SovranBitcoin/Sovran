id: F178
title: "Forced recovery can dead-end: timed-out mints keep restoring, and two states have no way out"
priority: high
needs: investigation
---

In `SettingsRecoveryScreen`: `withTimeout` cancels nothing, so a mint that timed out keeps restoring beside the next
one and after the run ends, retry is allowed meanwhile (the double restore the code warns about), and its late result
flips its row from timed out to done. In the forced recovery at startup, if every known mint is skipped the only
control is a disabled Continue; after "No mints found" the slider stays spent. Read from the code, not run; the
screen has no test for these paths.

## Done when

The recovery run is pinned by a test, a timed-out mint cannot overlap a retry, and every forced-recovery state has a control that leads on.
