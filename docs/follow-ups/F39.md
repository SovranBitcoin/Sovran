The active-account rule reaches `resolveNext`'s pickers only by accident: a mint across the testnut split reads as `MINT_METHOD_UNSUPPORTED`, and flow pickers happen to hide that reason code (`hideMethodUnsupportedCandidates`). The two rules are independent — `accountMintCandidates` is applied explicitly in `requestMintSelector` but not on the `handleAmountEntered` → `resolveNext` path, whose no-requirement branch lists `walletCtx.trustedMintUrls` unfiltered. No reachable leak was found (outside-account mints also carry a zero balance), so nothing was changed; a characterization test in `wallet/__tests__/flows/mint-selector-account-scope.test.ts` pins the current behavior.

## Done when

Every `selectMint` construction applies the account rule by name, not via a method-support reason code
