`wallet/src/screen-actions/availability.ts`: Cancel is available while a melt is PENDING (about line 396), and whether a
receive counts as redeemed is read from a `receive-` id prefix (about line 343), while Coco's own row id is
`receive:<op>` (`wallet/src/operations/receiveOperations.ts`, about line 154). So a rolled-back Coco receive offers
no Redeem. Pinned in `wallet/__tests__/unit/use-screen-actions-hook.test.ts` and
`app/__tests__/paymentRouteReentry.test.tsx`. Left because what Cancel should do on a payment in flight is a choice.

## Done when

Actions are decided from the operation's state, and Cancel is not offered where it cannot cancel.
