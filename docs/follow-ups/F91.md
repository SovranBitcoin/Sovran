title: "A wallet database for an unlisted account is never offered or deleted"
priority: medium
needs: device
---

A database for an account that is not listed is never offered or deleted. The other half is done in code and unit tests only: a listed account that this install has opened before, and whose wallet database comes up empty, now sets the restore to pending (`app/shared/lib/cashu/walletDatabaseRecord.ts`). Seen on the Android emulator on 2026-10-10 (dev build): with account 0's `coco.db` deleted, the next launch showed the restore screen; the same on the iPhone simulator with a release build. An account whose database was lost before this build first recorded it is still not noticed, and the restore status is one value for the install, so the restore holds every account until it ends.


**Done on 2026-10-12.** Delete-all removes databases by file as well as by list: `CocoManager.completeReset` reads
the SQLite directory and deletes every wallet database it finds there (the database, a journal or a pre-v2 backup
is enough to find it), and `deleteNostrCaches` does the same for the Nostr caches
(`app/__tests__/cocoBackupLifecycle.test.ts`, `app/__tests__/deleteNostrCaches.test.ts`). A database for an account
that is not listed is still never offered back to the person; delete-all is the only thing that reaches it.

**Left, on a phone or emulator:** with two accounts, delete one account's `coco.db` file by hand and reopen: the
restore screen must show. Then, with a database file present for an account that is not in the list (copy
`coco.db` to `coco-5.db`), run Delete All and check that the SQLite directory holds no `coco*.db` or `nostr*` file
afterwards.

## Done when

Delete-all removes databases by file, not by list; a device run deletes one account's database file and sees the restore screen on reopening.
