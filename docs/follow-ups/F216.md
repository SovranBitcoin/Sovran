In Network settings, an edit made while "Publish relay list" runs is stamped with the publish's result: the button
disappears and the edit stays local. Separately (suspected, not confirmed): the first-run publish treats a `null`
from NDK's `fetchEvent` as "no list anywhere", which would overwrite an imported account's real relay list if `null`
can also mean a timeout. `.surgery/pass-2/surveys/feed-social-nostr.md` D3, D9 and candidate 3 (traced; NDK not read). Left because it
touches the saved `source` field and what is published.

## Done when

A publish marks as published only the list it sent; the first-run publish is proven not to fire on a timeout, or is guarded.
