The declarative fixture runner includes every existing historical disk and supports explicit
preservation and transformation cases. Its field evidence report identifies raw saved leaves
without direct named assertions; it does not establish coverage of all enum members, optional
values, boundaries, cross-field combinations, interrupted writes or upgrade compositions.
See `app/__tests__/releaseFixtures/cases.json`, `cases.ts` and
`app/scripts/persistence/coverage.ts`.

This change establishes the shared runner and case format without inventing historical values
or rebuilding the frozen corpus. Public Android version history and pre-repository writer
commits also remain incomplete; installable EAS builds are evidence, not proof of publication.

## Done when

Meaningful cases are sourced from historical writers for uncovered store fields and variants,
with independent preservation expectations. Generated campaigns have deterministic seeds and
shrunk, actionable counterexamples; selected intermediate-upgrade and interrupted-write
schedules exercise actual storage boundaries. Coverage obligations fail when a new persisted
field or variant lacks a case or an explicit, reviewed explanation. Unknown public releases
and unavailable writer sources remain visible rather than silently counted as covered.
