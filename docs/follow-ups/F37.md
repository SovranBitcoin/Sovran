A testnut Nut Drop is announced in its REAL unit: the receive toast and the radar celebration read "Received 1,000 sats" (`nutDropAutoRedeem.ts`, `useNutDropCelebration.ts`, `NutDropCelebrationOverlay.tsx`). History and balances are scoped correctly; only the announcement is not. The picker's `NOT_IN_PAYMENT_REQUEST` copy ("Not accepted by payment request") is also shown for a nearby recipient's allow-list, where there is no payment request.

**Half done on 2026-10-12.** The picker now says "Not accepted by the recipient" when the allow-list comes from a
nearby recipient and keeps "Not accepted by payment request" when there is one (`wallet/src/mint-list-rows.ts`).

The announcement is left for the owner, because the fix the entry names does not work as written:
`formatAmount` (`app/shared/lib/currency.ts`) has no test-account unit, so handing it `tsat` logs an unknown unit
and prints a bare number. The receive toast for any other test-mint payment has the same wording, so this is one
decision for every "Received …" line. What should a payment from a test mint say?

- **A (recommended). "Received 1,000 test sats".** Teach `formatAmount` the test units once, spelled out, and
  use it in the toast and the celebration. Nobody mistakes it for real money.
- **B. "Received 1,000 tBTC-sats" or the tab's own label (tBTC).** Matches the account tab, but reads oddly beside
  an amount in sats.
- **C. Leave the amount as it is and add a "Test" badge** to the toast and the celebration.
