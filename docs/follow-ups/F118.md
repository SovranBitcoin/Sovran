---
id: F118
title: "The wallet counter guard reads then writes; one statement would close the window a transaction can use"
priority: medium
needs: fix
---

`wrapCounterRepository` in `app/shared/lib/cashu/cocoRepositories.ts` keeps a counter from going down by reading
the stored value and writing only a higher one. The read and the write are two statements, queued per keyset.
Investigated on 2026-10-12, from the installed Coco 2.0.0 (`@cashu/coco-core`, `@cashu/coco-expo-sqlite`):

- **A transaction can land between them.** On a phone Coco runs `withTransaction` through expo-sqlite's
  exclusive transaction, and the wrapper gives each transaction its own queue (sharing the root one could
  deadlock on the transaction lock). A root write that has read 0 can therefore save 3 after a transaction has
  saved and committed 9. The adapter's own statement is a plain overwrite
  (`ON CONFLICT ... DO UPDATE SET counter = excluded.counter`), so nothing below the wrapper stops it.
- **Reads are snapshots by Coco's design, not the wrapper's.** Coco reads the counter, derives outputs, then
  adds to it (`createOutputsAndIncrementCounters`, `createBlankOutputs`, `incrementCounter`) with no lock of its
  own around the three. Two concurrent reads answering the same number, and a read that answers lower than a
  value saved a moment later, are that design; whether two operations on one keyset can overlap is Coco's to
  guarantee, and belongs upstream if it does not.

What the app can close is the first: write the counter in one statement that keeps the larger value
(`SET counter = MAX(counter, excluded.counter)`), through the database handle the manager already holds, instead
of read-then-write. That needs no change to Coco, but it names Coco's table, so it has to be pinned by the wallet
database fixtures (`app/__tests__/cocoDatabases`).

## Done when

A root write that read a low value cannot lower a counter a transaction saved in between, with a test that
commits the transaction between the two steps; or the reason this cannot happen is written beside
`wrapCounterRepository`.
