An install upgrading from 0.1.3 has saved legs with `mintQuoteId` but no `mintOperationId`: an interrupted leg can
now reach `settling` and then never `done` (Coco offers `manager.ops.mint.listByQuote`, but a quote migrated from an
old Coco may have no operation row). Proofs can stay reserved for ever when a mint never answers again (the leg stays
payment-pending by design; nothing lets the person release them). Legs an old build marked `done` after a receipt
wait timed out are trusted. Saved legs do not say which plan step a route replaced, so with two plan steps between
the same two mints a real failure could read as replaced. A run ended by an account switch leaves money on a middle
mint when it stops mid-route, as Cancel does. The quote index is still stored beside the legs. Hot reload in
development loses run ownership.

## Done when

Upgraded legs finish from a quote lookup or are shown honestly; the person has a way to release reserved proofs once the mint confirms; each remaining item is repaired or ruled out.
